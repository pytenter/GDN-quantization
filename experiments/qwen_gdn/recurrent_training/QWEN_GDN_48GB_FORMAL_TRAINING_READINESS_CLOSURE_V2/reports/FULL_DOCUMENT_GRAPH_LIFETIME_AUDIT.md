# Full-document graph lifetime audit (before GPU smoke)

The canonical C5/C6 source SHA-256 is `48bd12d252c827ae57c48b2228d95e30de9f92baad47ebc2e8b64405b49e516e`. The frozen first training document, `wikitext2raw-train-000`, tokenizes to 1024 tokens. Its eight zero-based capture positions are 625, 663, 813, 819, 881, 940, 957, and 989. They fall in six H32 segments; two segments contain two captures, so at most **two captured loss tensors** are stored simultaneously before a segment backward.

At each capture, the canonical patch computes the 24-layer-averaged state-relative-MSE C5 loss, or for C6 the functional-relative-MSE plus `0.1 × state-relative-MSE`. The selected combined loss is scaled globally by `1/8` and appended to `segment_losses`. At every H32 boundary (or document end), the code sums that segment's losses, performs backward if nonempty, clears the loss list and patch captures, then detaches the recurrent, convolution and KV cache. Theta gradients accumulate across the document; Adam steps once after the final token. The teacher targets are detached CPU tensors, not retained autograd graphs.

Therefore the current canonical implementation **does not hold multiple detached H-segment graphs until a document-end backward**. The live graph is the current segment's student cache plus at most two captured losses for this document. No streaming-backward redesign is applied or authorized here; the requested mathematical fallback remains only a possible future experiment if a real full-document memory failure is observed.

The canonical validation function runs the frozen 16-document, 1024-token-per-document panel with no-grad student forward; it detaches cache every H tokens and releases cache/targets between documents. The formal training cadence first validates at 50 target exposures; a three-update readiness smoke reaches only 24, so the planned validation call is an explicitly forced diagnostic boundary using the unchanged canonical validation function, not a formal-cadence modification.
