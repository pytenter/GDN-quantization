# Environment and source parity

The training host is `autodl-container-a88f4a8a56-14ae8f67`. It exposes exactly one `NVIDIA vGPU-48GB` CUDA device (47.3819 GiB reported by PyTorch, compute capability 8.9), driver 570.124.04. The 50 GB XFS data disk is `/root/autodl-tmp`; after the 19,329,394,438-byte single model copy, it had approximately 31.1 GiB free at the audit. The independent environment is `/root/miniconda3/envs/qwen-recurrent` on the system disk.

Python 3.10.18, Torch 2.5.1+cu121, CUDA runtime 12.1, NCCL 2.21.5, the original editable Transformers 5.16.0.dev0 source, Triton 3.1.0, NumPy 2.2.6, safetensors 0.8.0, and tokenizers 0.23.1 match. FLA is absent on both hosts. `flash_attn` 2.6.3 is installed only on the original host, but both loaded model configurations selected `sdpa` in this diagnostic. Other noncore package differences are enumerated in `configs/package_delta.txt`; both full package inventories are retained.

`VGPU_MEMORY_GATE=PASS` and `SOURCE_HASH_GATE=PASS`. Exact SHA-256 checks cover the model config and safetensors index, canonical C5 source (`48bd12d252c827ae57c48b2228d95e30de9f92baad47ebc2e8b64405b49e516e`), Cayley/QDQ source (`62e769dfad73170279daf0bdb56855b7d7e4aaf77478de897958fa87b2608067`), Qwen modeling source (`90d929129ffc835d2652c604925c4f3842bc6e401e174ec6f0db2285dfb8f85a`), fixed corpus, and frozen train/validation/eval manifests. Server-only source paths and hashes are recorded in `configs/source_provenance.json`. No old raw traces, AIME generations, or second model copy were transferred.

The fixed `TRAIN:first-row` 64-token teacher endpoint was regenerated on the original server. Its input, logits, loss, block-15 boundary, and sampled recurrent-state hashes matched the prior historical reference. The original-to-vGPU comparison used the same input and source and was finite throughout. The input IDs matched exactly; the logits had max absolute difference 0.203125, relative L2 0.0105668, cosine 0.9999261; the C5 teacher loss differed by -0.1200161 on vGPU. Selected recurrent states and all other tensor metrics are in `analysis/forward_parity.json`. No cross-GPU numerical tolerance was preregistered, so these differences are reported without a post-hoc scientific pass/fail threshold. They did not indicate a structural source/input mismatch.

An initial reference-probe hook accidentally returned a CPU copy as the block-15 forward output, causing a device mismatch before any reference artifact was written. The probe was corrected to return `None`; subsequent original teacher output exactly matched the historical reference. The canonical model implementation was not changed.
