# Runtime 边界静态审计

CURRENT_RUNTIME_IDENTITY=PASS 仅指已定位、当前读取并核验的源码身份。GPU上实际dispatch、FP_H-native功能等价、baseline end-to-end、GPU determinism均NOT_RUN。本轮没有导入训练/model runner；CPU测试只AST提取冻结的纯量化函数。

## 两条历史边界必须区分

1. 旧正式AIME runner `formal_c128_runner.py:400–428`：初始prefill返回后先采样首个token，不立即quantize_c128；后续单tokenforward之后、下一次采样之前才QDQ。它不能直接证明从第1个consumed token起逐步QDQ的新canary与旧AIME端到端一致。
2. 后续正式逐token路径 `scale_science.py:181–195`：每次forward只传[[token]]；第1token走chunk（空cache），随后单token走recurrent；model返回后对全部24层调用原quantize_c128且audit calls=1。这个路径用于新canary的边界设计；不是把128token一次prefill末的单次量化当逐tokenQDQ。

## 精确顺序

输入token → 原embedding/block → Q/K/V投影及原conv/update → head reshape → sigmoid beta、FP32 decay g → 16个Key头repeat为32个Value头 → 原必要Q/K归一化 → 仅Q/K的Key坐标Hadamard → 原GDN更新/当前readout → cache更新 → 原gated RMSNorm/gate/out_proj和剩余层/logits → 完整forward返回 → 外部每层QDQ/writeback → 下一token读取同一cache。

`current_modeling_qwen3_5.py:494–535` 和 `formal_c128_runner.py:175–218`：K=V=128、state=[B,32,128,128]；H为固定归一化Sylvester128。normalize_qk保持其原运算dtype/order，不偷偷提前改成FP32 normalization；然后value.float()@H，Value不旋转。Q/K规范转换严格用该函数，不能另外重新旋转state。

GDN torch recurrent函数将q/k/v/beta/g转FP32。Sminus=exp(g)*Sprevious，residual=v−kᵀSminus，Splus=Sminus+k⊗(beta*residual)，readout=q_scaledᵀSplus。**当前token readout使用QDQ前的updated state**。helper结果按原H wrapper转回Value dtype，随后原gated RMSNorm/out_proj，不把encode插进这些路径改变当前token输出。外部quantizer在整次model forward完成后写回；首token current logits因此不应依赖该token刚结束才发生的QDQ。

下一token的 `initial_state` 必须与上一步QDQ写回一致；当前Harness:149–150有显式torch.equal检查，:189–194检查24层写回与原函数输出。新adapter尚未在GPU复现这些证据，不能预填PASS。

C128原函数source=state.detach().float()；Key轴-2的absmax先clamp_min(1e-12)再/127；torch.round ties-to-even；clamp[-127,127]；codes*scale；检查finite；copy_(dequant.to(state.dtype))。scale FP32、临时整数codes FP32。新CPU物理对象的int8 codes+scale并不代表旧runtime物理cache：原cache是完整FP32 QDQ值，允许的逻辑QDQ语义与物理resident INT8资格分开记录。

## 当前数值与kernel身份

8-doc SOURCE_AND_RUNTIME_IDENTITY及实际依赖SHA显示：当前qualified路径采用V3 FP32 Neumaier compensated scan，Torch2.5.1+cu121、CUDA12.1、TF32 false、strict deterministic、CUBLAS=:4096:8。`numerical_recovery.chunk_binding`从实际架构AST只替换唯一 g.cumsum 调用，其他chunk体保留；本轮不切换或重写kernel。

保留原Torch/cumsum/native bitwise FAIL、fixed-route full-model FAIL和文档配对STOP；NEW_MATCHED_NUMERICAL_CONTRACT只使compensated路径在其既定matched panel合格，不追溯将旧FAIL变PASS，也不自动使新H-only/新GPU组合合格。新H-native等价/当前GPU跨进程检查仍须另行授权后实际完成。

架构包含Hub kernel decorators（FLA与conv fallback）。当前installed metadata未找到flash-linear-attention/fla-core distribution，**不等价于证明live dispatch必定无外部kernel**。当前绑定静态路径已记录；未来必须在实际模型加载后核验真实helper/callsite和dispatch身份，不能借装饰器默认行为绕过数值资格。CPU-only阶段没有调用这些decorator runner。

FP_H与native的功能比较应对齐logits/final-hidden/Value坐标readout；对state边界资格，H@S_H与S_native在同一物理坐标比较，仅用于审计，不将native缓存后乘H冒充真实H轨迹。学生与FP_H state比较则直接在同一H坐标下进行。共同输入、权重、token位置、cache初始化和QDQ时点必须一致。
