S\in\mathbb R^{d_k\times d_v}

固定 Value Column，沿 Key 维度每 32 个元素共享一组 Scale 和 Zero Point。

4. 使用整数 Zero Point。
5. 确保零能够被精确表示。
6. 正确处理 Clamp 和 Saturation。
7. 正确处理全零、常数及极值 Group。
8. 使用论文对应的舍入规则。
9. 不产生 NaN/Inf。
10. 提供 CPU Reference 与 GPU 一致性测试。

不要把 Row Grouping 误认为 Column Grouping。

不要使用 Hadamard、BitRev、QEig 或任何额外 Rotation。

## 5. 实现 PACE Head 重要性选择

严格使用：

\[
E_h=\frac{e_h}{1-a_h^{2dP}}
\]

本轮 Head Selection 按 PACE 原版：

\[
dP=8
\]

即：

\[
E_h=\frac{e_h}{1-a_h^{16}}
\]

其中：

- \(e_h\)：Head 的单次量化误差能量。
- \(a_h\)：Head 的平均衰减系数。
- \(E_h\)：估计的误差持久性评分。

使用非 AIME 数据执行离线校准。

按照论文要求使用 8 个独立的 2048-token 校准窗口，并严格核对论文对误差统计与衰减聚合的定义。

每层按照 E_h 排序：

- 最高风险 25% 使用 INT8。
- 剩余 75% 使用 INT4。

生成并保存：

- `head_scores.csv`
- `head_mask.json`
- `calibration_manifest.json`

**R2 和 R3 必须加载完全相同的 head_mask.json。**

禁止使用 AIME26 数据选择 Head。

禁止依据最终 AIME 成绩调整 Head Mask。

## 6. 实现 dP8 Periodic Decoding

这一部分是本次最重要的工程任务。

R2 必须真正使用 PACE Periodic Decoding。

不能简单地让一份完整 FP32 State 常驻，每 8 个 token 才做一次 QDQ，然后宣称实现了 PACE。

正确流程：

1. 持久保存量化后的 Recurrent State。
2. 缓存最近 token 所需要的 Key、Value、Decay 等更新信息。
3. 利用 Quantized Base State 和 Decode Buffer 计算每个 token 的正确输出。
4. 每满 8 个 token 执行一次 Chunk State Update。
5. 对更新后的完整 State 执行一次量化写回。
6. 清理或推进 Buffer。
7. 处理不足 8 token 的尾部情况。

R3 使用同样的计算语义，只把周期改为 1。

需要检查：

- Key Normalization。
- Delta Rule Update。
- Gating / Decay。
- Token 顺序。
- Prefill 到 Decode 的转换。
- Chunk Boundary。
- State Writeback。
- EOS。
- Context Length。
- Buffer Precision。

### 数值正确性门禁

正式评测前，至少通过：

**Gate A：Quantizer Numerical Tests**

Sym/Asym 的编码、解码、Zero Point 和 Grouping 正确。

**Gate B：FP Buffer Parity**

关闭 State Quantization，验证 Chunk-wise Buffer 与原生 FP GDN 的 State 更新和 Token 输出在预设数值容差内一致。

**Gate C：Quantized Buffer Tests**

验证 R2 和 R3 均使用正确的量化 State、Decode Buffer 与写回周期。

**Gate D：Full-model Smoke**

使用少量非 AIME 文本检查正常生成、数值稳定性与显存。

这些门禁不属于新增正式实验配置。

如果某项失败，定位并修复根因，重新执行相关门禁。

不得通过放宽数值阈值或删除失败样本来通过测试。

### A. 正确率差异

\[
\Delta Acc=Acc(R2)-Acc(R3)
\]

### B. 逐题 Rescue / Regression

比较同一道题在 R2、R3 下的结果。

- Both Correct。
- R2 Only Correct。
- R3 Only Correct。
- Both Wrong。

### C. 生成行为

比较：

- Mean Token Length。
- EOS Rate。
- Length-Capped Count。
- 重复或异常生成。
- Nonfinite / Runtime Errors。

### D. 性能和内存

报告：

- Total GPU Runtime。
- Mean Runtime per Problem。
- Peak VRAM。
- State Payload bits/value。
- Scale / Zero Point 开销。
- Decode Buffer 开销。
- Total Resident bits/value。

同时区分理论压缩量与实际物理存储。
