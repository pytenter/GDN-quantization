## 1. 必读历史科研基线

### 1.1 最新冻结科学结果

Qwen3.5-9B/GDN，严格persistent recurrent-state INT8量化。

AIME26 Canonical60：

| Method | Result |
|---|---|
| FP | 52/60 |
| Hadamard | 41/60 |
| C6R | 40/60 |
| C7 | 33/60 |
| Native INT8 | 18/60 |

C6R采用Functional-oriented learned orthogonal rotation，原训练目标包括GDN局部Functional loss以及0.1倍State loss。

最新32K五文档结果：

| Method | Mean Future-KL |
|---|---:|
| H+C128 | 0.073269615054 |
| C6R+C128 | 0.073770261773 |
| H+Dual-M | 0.029374825437 |
| C6R+Dual-M | 0.036156791107 |

已经确认：

- Dual-M在Hadamard下5/5文档改善Future-KL。
- Dual-M在冻结C6R下5/5文档改善Future-KL。
- C6R+Dual-M仍仅1/5文档优于H+Dual-M。
- Rotation × Codec interaction为2正3负，不稳定。
- 历史五篇文档已被观察，项目独立性UNKNOWN。
- 这些结果不证明重新训练旋转一定有效。

本次新训练的核心动机是：

**原C6R主要针对C128优化，其旋转结构可能没有适应Dual-M量化误差，因此值得检验在Dual-M下重新优化旋转是否能产生额外收益。**

这只是待验证假设。

## 2. 冻结新的科学问题

本次准备的后续正式训练研究：

**Does codec-aware orthogonal rotation optimization improve Qwen/GDN functional accuracy under persistent Dual-M INT8 quantization?**

设计两个配对训练条件。

### Arm A：C128-aware Rotation

```text
INITIAL_ROTATION = HADAMARD
TRAINING_CODEC = CANONICAL_C128
LOSS = FUNCTIONAL + 0.1 * STATE
OUTPUT = R_A
```

### Arm D：Dual-M-aware Rotation

```text
INITIAL_ROTATION = HADAMARD
TRAINING_CODEC = DUAL_M_INT8
LOSS = FUNCTIONAL + 0.1 * STATE
OUTPUT = R_D
```

两组必须满足：

- 完全相同的Hadamard初始化。
- 完全相同的可训练参数集合。
- 完全相同的正交参数化。
- 相同训练数据及顺序。
- 相同teacher targets。
- 相同优化器、学习率及gradient clipping。
- 相同训练步数。
- 相同gradient horizon和detach策略。
- 相同训练时数值配置。
- 相同checkpoint规则。
- 相同训练和验证数据边界。

**两个训练条件唯一计划中的科学变量是训练时使用的quantization codec。**

不能一组采用persistent student，另一组采用FP state reset。

不能一组训练更多steps。

不能一组使用clean-FP scale oracle，另一组不使用。

不能先观察结果，再为某一组调整学习率、loss权重、gradient horizon或checkpoint选择规则。

冻结C6R和Hadamard均作为最终比较基线，不在本次重新训练。

### 训练目标

沿用原C6R真正使用的Functional/State定义。

计划比较：

\[
L_A(R)=L_{\mathrm{func}}(R,Q_{\mathrm{C128}})
+0.1L_{\mathrm{state}}(R,Q_{\mathrm{C128}})
\]

\[
L_D(R)=L_{\mathrm{func}}(R,Q_{\mathrm{DualM}})
+0.1L_{\mathrm{state}}(R,Q_{\mathrm{DualM}})
\]

必须先核实原Functional定义与RMSNorm、gate、readout/out_proj的真实关系，不根据名称重新实现Loss。

不允许本次增加：
- Scale Inflation Penalty
- Temporal Lifetime Loss
- Future Query Readout Loss
- CVaR或新的tail-risk loss
- 新的lambda权重
- Dual-W
- FP16重要行保护
- mixed-bit quantization

## 3. Phase 0A：Dual-M训练前向正确性

这是决定能否租A800的第一个核心门禁。

复用已完成32K实验中经过验证的Dual-M算法。

固定：

```text
BITWIDTH = INT8
PIVOTS = 0
ROW_SCALE = FP16
COLUMN_SCALE = FP16
IMPORTANCE_WEIGHT = 1
COLUMN_LS = FROZEN_REFERENCE
FINAL_REENCODE = FROZEN_REFERENCE
```

Dual-M前向必须与已经用于正式推理的真实算法一致。

State经旋转后，执行真正的Dual-M quantize/dequantize/writeback。

下一token必须消费已经QDQ写回的状态。

训练中允许反向传播所需的临时高精度张量，但不能把跨token未量化FP state替代真实student递归状态。

需要CPU验证：

1. 与正式Dual-M codec的code一致性。
2. Row/column scale一致性。
3. Reconstructed state一致性。
4. FP16 scale边界。
5. Zero/outlier/ties等极端输入。
6. 真实state tensor shape与rotation axis。
7. 每token recurrent QDQ语义。
8. C128原训练codec parity。
9. Hadamard/Cayley正交性。
10. 模型功能坐标一致性。

必须使用真实冻结reference比较，记录允许的数值差异及其来源。

如果Dual-M训练前向无法在原数学定义下复现正式推理codec：

`DUAL_M_FORWARD_PARITY = FAIL`

立即STOP。

不得为了训练方便改变Dual-M scale规则、LS迭代数、clamp或rounding语义。

## 4. Phase 0B：反向传播设计和验证

这是本次任务最重要的技术工作。

Dual-M包含非光滑计算：
- INT8 rounding
- clipping
- FP16 scale conversion
- row/column scale estimation
- column least-squares fitting
- final re-encode

不能简单把原C128训练函数替换成Dual-M后就认为梯度正确。

首先检查原C6R训练的STE/autograd实现。

制定一个明确、固定、可审计的Dual-M backward policy。

要求：

- forward始终执行真实Dual-M数值计算。
- backward的surrogate规则事前固定。
- 明确哪些scale路径允许梯度。
- 明确哪些scale路径detach。
- 处理量化截断边界。
- 不允许使用仅在训练阶段存在、但没有被记录的不同codec前向。
- 不通过改变Dual-M前向来制造更容易训练的梯度。

优先使用最小、可解释的STE设计，不引入复杂的custom CUDA backward，除非原合格实现明确要求。

### 梯度资格测试

CPU及可行的3090 micro-test必须验证：

1. Loss finite。
2. Rotation参数gradient finite。
3. Gradient不是全部零。
4. 不存在NaN/Inf。
5. 原C128分支对同一输入的梯度行为与历史实现一致。
6. Dual-M反向路径确实连接至可训练旋转参数。
7. 正交矩阵在更新后仍满足冻结正交误差要求。
8. 固定seed的重复训练步骤结果一致，或符合事前定义的确定性合同。
9. 三个连续micro-updates可以完成forward/backward/optimizer step。
10. checkpoint恢复能够正确恢复optimizer、rotation和RNG状态。

对于光滑的连续计算部分，可以使用有限差分检查解析梯度。

但不得要求STE的surrogate梯度与包含hard rounding的真实前向有限差分完全一致，因为两者本来不一定相等。

STE的正确性应通过计算图、局部单元测试、梯度覆盖和优化行为验证，并诚实说明surrogate的边界。

不能把micro-test loss短期下降当成32K收益证据。

如果需要重新发明大量autograd或重写GDN CUDA kernel才能反向传播：

`TRAINING_GRADIENT_GATE = FAIL_CLOSED_STOP`

不进入无限工程开发。

```text

H + DUAL_M
C6R + DUAL_M
R_A + DUAL_M
R_D + DUAL_M
```

至少准备两篇全新、合法、未见的32768-token文档作为下一次探索性测试。

每篇384个固定评分位置：

```text
t = 8192 + 64*k
k = 0,...,383
```

Full-vocabulary FP32 KL：

```text
KL(FP_NATIVE || STUDENT)
```

使用冻结的math.fsum/384 reducer及算术复核方式。

所有student必须从token0构建自身persistent QDQ历史。

三个主要未来比较：

```text
G_specific =
  K(R_A, DualM) - K(R_D, DualM)

G_adapt =
  K(C6R, DualM) - K(R_D, DualM)

G_H =
  K(H, DualM) - K(R_D, DualM)
```

解释：

- G_specific > 0：Dual-M-aware训练优于等预算C128-aware训练。
- G_adapt > 0：新训练优于旧C6R。
- G_H > 0：新旋转在Dual-M下超过Hadamard。

建议G_specific为未来主要科学比较；G_H是关键性能目标。

所有定义、统计单位、数值分辨率规则必须在正式训练前冻结。

测试文档必须在不查看模型结果的条件下选定。

N=2仅属于探索性科学测试，不能宣称统计显著或广泛泛化。
