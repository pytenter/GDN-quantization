# Runtime presets 使用边界

当前`ALLOW_GPU_DIAG=NO`；状态是CPU准备完成、GPU资格未运行。Strict配置参考[STRICT_RUNTIME_CONTRACT.md](/Users/pytenter/Documents/临时项目1/QWEN_GDN_FAST_RUNTIME_QUALIFICATION_V1/STRICT_RUNTIME_CONTRACT.md)及机读[STRICT_BASELINE_CONTRACT.json](/Users/pytenter/Documents/临时项目1/QWEN_GDN_FAST_RUNTIME_QUALIFICATION_V1/analysis/STRICT_BASELINE_CONTRACT.json)。候选`:16:8`尚未通过数值/性能/Codec资格，不是可投入使用的Fast Runtime。

- `strict_runtime.sh`是冻结NEW_STRICT配置与身份包装；只接受`--help`、`--check`（CPU-only本地source manifest检查与不导入torch的package metadata记录）、`--print-env`（打印冻结exports）。它不接受任意命令、不加载模型，也不启动GPU/长任务。预置`:4096:8`、OMP/MKL1、离线模式及bytecode禁写。CPU检查不是GPU数值PASS。
- `runtime_identity.json`或对应机读合同绑定实际源/参数；不得悄悄回退。完整weight/tokenizer/依赖身份须按计划核验；未来loaded动态库和GPU实际环境必须记录。
- 未生成`fast_validated_runtime.sh`。也不能把候选配置改名作Fast脚本或直接应用已封存AIME Runtime。
- FP通过不自动通过H+C128或H+Dual-M。原Dual-M当前候选为`NOT_QUALIFIED_FOR_THIS_CODEC`，Fast应拒绝它；Group32、Asymmetric等未测试方法同样不能继承资格。
- 不自动运行AIME、32K Future-KL、训练或长程评测；短资格不保证32K/81K全路径一致。

资格worker接口（只说明程序入口，不提供当前执行授权）：

```text
scripts/cublas_worker.py --root ROOT --unit-id ID --mode qualify|benchmark --condition B0|B1 --codec FP|H_C128 --authorization AUTHORIZATION_JSON
```

GPU入口仅`python scripts/run_cublas_controller.py --run --allow-gpu-diag YES --authorization AUTHORIZATION_JSON`，且必须已有本任务人类明确YES以及所有真实准入PASS；这里的命令说明不是授权。正常使用先阅读启动器帮助与冻结授权，不直接调用worker绕过控制器；raw worker也必须自行拒绝未授权/身份失配。没有通过字节等价、fresh重复性、安全/资源和稳定收益全部门禁前，Strict与Fast之间不存在已批准切换。

科研协议选择：Strict用于原协议定义内复现与对照；只有未来`FAST_STRICT_EQUIVALENT_VALIDATED`且注明具体Codec/长度范围时，Fast才可作为相应新实验等价候选。若仅`FAST_NEW_PROTOCOL_REPRODUCIBLE`，必须整套匹配基线在新协议中重建，不能直接与旧Future-KL/AIME作Codec因果比较。

原native recurrent-cache是FP32逐tokenQDQ carrier，不能宣称persistent packedINT8。配置快并不替代量化状态/数值语义资格。
