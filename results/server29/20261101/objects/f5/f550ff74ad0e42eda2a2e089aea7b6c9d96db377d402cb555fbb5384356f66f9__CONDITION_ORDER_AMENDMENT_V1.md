# LING L6/L7 Canonical-60 Condition-Order Amendment V1

The user prospectively authorized this amendment while Hadamard generation was still in progress and before any new canonical L6 or L7 output existed on either formal host.

The formal execution order is amended from:

```text
H -> L6 -> L7
```

to:

```text
H -> L7 -> L6
```

Hadamard continues without interruption. After all 40 missing Hadamard samples complete, outputs from the two formal hosts must be synchronized to the 4090 worktree and pass every frozen scientific, artifact, runtime, semantic, quantizer, budget, assignment, scorer, JSON, SHA256, token-provenance and process gate. Only then may L7 start. L6 may start only after all 40 L7 outputs complete, synchronize, and pass the same gates.

This amendment changes only execution order. The original preregistration, hardware assignment and frozen configuration remain immutable. It does not change the sample set, seeds, prompts, context or token budgets, model, runtime, quantizer, rotations, scorer, per-sample GPU assignment, concurrency, retry policy, endpoint definitions, or statistical plan. Existing frozen-20 outputs remain reuse-only and must not be regenerated.

If evidence appears that any L6 or L7 canonical output existed before this amendment was frozen, the prospective-order gate fails and formal downstream generation must stop for audit.
