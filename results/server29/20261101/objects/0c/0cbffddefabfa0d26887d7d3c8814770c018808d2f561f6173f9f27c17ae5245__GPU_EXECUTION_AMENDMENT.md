# 四卡执行、资源与存储修订

任务 `QWEN_GDN_FAST_RUNTIME_QUALIFICATION_V1` 的本次执行为 `QWEN_GDN_FAST_RUNTIME_QUALIFICATION_GPU_20261019_V1`。人类明确授权：“可以开始GPU，同时用四张卡都可以，并且没有GPU时间限制”。本修订只改变先前 GPU 授权、物理设备映射、资源限额与原始快照存储；原 CPU 151 文件封存及科学与数值规则保持可核验。绑定信息见同名 JSON，人类授权的原文与 SHA 另行保留。

四个独立设备层分别绑定 GPU0–3 的 UUID，每层内 B0/B1 使用同一设备，逻辑设备仍为 cuda:0。每卡使用相同的有限 16 单位清单：4 次 FP 数值资格、6 次 FP 性能、仅当该卡通过原收益阈值时执行 2 次 FP profile 和 4 次 H+C128 数值资格。每个数值单位完整执行 256 输入，B0/B1 各两个 fresh 进程，与本卡本 codec 的 B0_Q0 比较完整逐 token logits、cache、GDN 中间量字节；不跨卡比较字节，不汇总四卡 TPS。

先等四卡 FP 数值资格全部 PASS，再使用共享互斥锁顺序执行每卡的六次性能单位，避免四组性能测量争用 CPU。全部四卡性能单位终态后才进入符合条件设备的 profile/H 组。性能仍是 128 warmup +128 measure、三次配对；只保留原边界同步。原收益规则为该卡 B1 中位 TPS 相对 B0 至少增加 5%，且 min(B1)>max(B0)，不增加或改变阈值。共享首次失败阻止后续派发；共享离线启动器也处理子协调器在准入阶段退出的情况。

移除旧 0.5 GPUh/1800 秒累计或总墙钟上限、1650 秒保护停止和单位耗时终止。预计耗时字段仅为估计。1800 秒仅表示**没有已提交进度**的 watchdog；固定 I/O timeout 仍用于发现失联，实际资源占用须持续记录。未授权重复失败单位或无限运行新单位。

原始快照直接流式写入 .29 永久目录的 gpuN 子目录；.55 与 Mac 只保留元数据和核验回执。每卡保留 200 GiB 存储资格，共预留 800 GiB 并保留 100 GiB 余量；.55 新根至少 4 GiB。每次写入须独立逐字节 SHA/bytes 核验与原子封存，后续 fresh 进程从远端引用流式复核，首个差异留远端。必须先完成实际 .29 容量/权限/连接与真实 CPU 传输读写、重复路径拒绝资格；容量历史描述不能代替实际 PASS。不会把大 tensor 下载 Mac，也不删除历史资产。

原请求 D3 的 Dual-M 资格仅在可访问原 codec、该设备 FP 严格数值与原性能收益均通过时成立。当前 16 单位不包含 Dual-M；必须等当前四卡全部进程退出并核验释放，再以独立 codec 根与新源/预注册封存执行原完整 256 数值门禁。每个符合条件设备共 4 次 fresh（B0 两次、B1 两次），不是每个条件四次。不得热修活跃程序，不能继承 FP/H 的 TPS。无收益或失败的设备跳过 D3。

本修订和本地 builder 是 CPU 交付，尚不代表实际 GPU、数值、速度或归档门禁通过。新授权、清单、源依赖、模型与实际库选择、父进程与派发身份、UUID、有限单位清单仍须在真实执行前逐项准入。
