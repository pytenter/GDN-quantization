## Semantic boundary

A = executable/code-bearing: actual process execution and native executable
mapping, imported/compiled/executed Python origins, observable file-backed JIT.
B = scientific/numerical inputs: model, checkpoint, rotation, tokens/documents,
scientific config and frozen inputs. Both require closure and content identity.
C = ambient OS metadata/config: read-only support data with recognized role,
consumer and format; record path, SHA256 for regular files, role, reason,
read-only ingress and observation. D = unknown, always blocking.

There is no exact-path exception for locale aliases. Locale resolution alias
data must satisfy the same two-field locale grammar independent of its basename,
be in an OS support-data location and be consumed by an already-closed git
identity/status executable using the bounded read-only identity commands.
Timezone data requires TZif format and OS timezone-support location/use. In
qualification, a post-bootstrap arbitrary Python consumer is not automatically
OS support: the audit-install phase marker removes that presumptive role.
GNU gettext catalogs require catalog format and bounded git metadata consumer.
Synthetic semantic consumers are test-only and are absent from qualification.
The launcher explicitly rejects the synthetic consumer switch in qualification.

Ambient classification is not a code/numerical input permission. Subsequent
code/scientific use upgrades the classification and blocks pending explicit
closure authorization. Writes to previously observed ambient paths block.
Regular ambient bytes are rehashed after successful qualification. Former
advisory prefixes are not silently ignored; unrecognized regular files are
closed as A/B only under frozen asset policy, otherwise D and STOP.

Independent ptrace covers reads, mappings and traced descendants. An additional
cooperative Python origin audit acknowledges import/compile/exec file origins
and rejects direct compilation of observed ambient bytes. No function-name or
code-object whitelist; no old scientific code mutation. This is not an
adversarial information-flow/taint sandbox. Unsupported ingress or ambiguous
consumer semantics fail closed; no claim of complete qualification before A/B
and post-commit suites. Native pre-exec checks conservatively reject an existing
unauthorized candidate before execution; nonexistent PATH probes contribute no
successful ingress. Successful execution is independently checked through maps.

Record LANG, LC_ALL, LC_CTYPE, LC_NUMERIC, LC_COLLATE, PATH, active locale and
localeconv before/after. Do not set locale or change any numerical environment.
