二、本轮科学问题
==================================================

PRIMARY QUESTION：

在新的独立RepoBench-P长文档上，
持续限制Scale Inflation是否能够
降低真实full-model persistent INT8模型的
长期Future-KL？

PARENT
vs
NO_SCALE_INFLATION

使用相同模型、相同C6R旋转、
相同teacher-forced tokens、
相同8192-token学生历史和matched FP reference。

每个文档的主要因果效应：

Delta_i =
K_PARENT_i - K_NOINFLATION_i

Delta_i > 0：
NoInflation改善未来KL。

Delta_i < 0：
NoInflation使未来KL增大。

数值不可分辨时：
UNRESOLVED。

本轮不验证旋转排名能力，
也不验证Loss梯度可训练性。

特别注意：

NoInflation使用clean FP scale作为oracle。

这是诊断性干预，不是部署方案。

- 384位置full-vocab FP reference logits
- 完整identity和finite proof

STEP 2：
构建共同Persistent Student Anchor。

采用原C6R persistent INT8-C128路径，
消费完整前8192 tokens。

每token真实QDQ/writeback。

保存完整student anchor：

- GDN recurrent state
- hybrid/attention KV cache
- convolution cache
- position/RoPE metadata
- tokenizer/token index
- runtime/quantizer identities

STEP 3：
从同一anchor恢复Parent。

保持原始adaptive scale，
持续运行到32768。

计算384位置完整词表Future-KL。

STEP 4：
从完全相同的anchor恢复NoInflation。

使用：

s_effective=min(s_student,s_clean)

保持其他所有量化与完整模型计算语义不变。

持续运行到32768。

计算相同384位置Future-KL。

不得从Parent已经演化到中途的state
fork出NoInflation。

也不得使用FP clean-state作为student anchor。

两个student branch从同一8192状态分叉，
随后各自独立演化。

STEP 5：
完成该document的原子结果封存。

记录：

FP identity
anchor identity
Parent identity
NoInflation identity
384 KL values
intervention activation
clipping/saturation
resource consumption
completion receipt
SHA256

正式结果不得根据一篇表现改变下一篇计划。

如果某个branch失败：
