# C6R 数学与运行路径只读审计

CPU 身份、坐标和最小适配审查通过；这份 PASS 仅属于 CPU 范围，所有新 GPU 门禁仍为 NOT_RUN。没有运行模型或 CUDA，也没有修改任何历史文件。

精确 C6R 是 A800 matched 训练 update 94、exposure 752 的导出，完整 SHA256 为 `a886588b3613f66e6635e5874dbfaeaee26b850e05b4a1524da0bef952d22da6`；正式部署 manifest SHA256 为 `f365dbab44e31b127abc5f9cc37916e432c4f3c88cc7706c82886812686d1103`。本次 CPU 重新读取两份同字节导出、manifest、checkpoint_selection 和 Canonical60 runtime 绑定；24 层 FP32 128×128 矩阵的每层 SHA、有限性、形状、条件、更新号全部吻合。具体远端路径、哈希前后 stat 和逐层哈希见 C6R_ROTATION_IDENTITY.json。没有从 theta 重建矩阵。

原 `formal_c128_runner.py` 与 canonical generator 的完整 SHA 都是 `77b1e1f6dad8a0dd53a27cf5a47c02be86c26d2cf30732604ba6d3747e178f69`。最小适配直接提取原 FrozenRotationLayer/Bank、load_frozen_rotation、QwenFrozenRotationPatch 及其原 hash 依赖。原函数在 normalize_qk 后先计算 q/k.float() @ H128，再单独 @ Delta_l；禁止预合成。每层 Delta 在该层全部 head 共用。

按原 GDN 存储 `[B,H,K,V]`，C6R 是 key 轴坐标变换：S_stored=Delta_l.T@(H128@S_native)，恢复是 H128@(Delta_l@S_stored)。value、g、beta、当前读出和 out_proj 不增加旋转。原 C128 仍直接调用原 quantize_c128，沿 -2 的 key 轴取绝对最大值，每 value 列一个尺度；Dual-M 沿原最后两个轴处理，同一 codec 在 C6R 存储坐标执行，不在原始坐标额外 QDQ。矩阵只近似正交，不能把有限精度恒等断言为严格 FP 等价。

现有 core 的原 recurrent helper 和 V3 compensated chunk_binding 可原样保留。新 entry 只把 run 内两个条件字符串改为 C6R_C128、C6R_DUAL_M，逆替换 AST 与原 run 完全一致；实际旋转上下文由原 C6R 类构造。原核心四文件字节不改。四卡适配复用已资格 control 的原 configure_ast 和 checkpoint hook：仅首条 physical visibility 比较器变化，数学、seed、determinism、TF32、dtype、logical cuda:0 语句相同；完整原 checkpoint 函数加全任务文件锁，主任务只保留一个 rolling CURRENT。

本次不执行 FP/H GPU forward。每卡旧非五文档 canary 仅跑 C6R 的 5 条 initial（A_REFERENCE、A_OFF、A_ON、D_OFF、D_ON）和 2 条 fresh（A_FRESH、D_FRESH）；正式只允许 10 个 C6R 标签。原观察/评分/每 token 持久 QDQ/下个 token 消费/restore 路径保留，额外逐轨迹检查原 C6R patch 恰好调用 24×tokens 次。CPU mock 包含 canary 调度、receipt、参考不一致 fail-closed、四卡首条断言 AST 差异和原 checkpoint hook 测试。
