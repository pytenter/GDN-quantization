# Codex 任务：Qwen3.5-9B GDN — HMMT February 2026 四配置正式评测

## 0. 总体目标与工程授权

本任务是 Qwen3.5-9B GDN Recurrent-State Quantization 研究的一次独立 Benchmark 验证。

此前已经完成 AIME26 的 PACE + LeapQuant-style Direct Read 对照：

- `LQUnroll+dP8`：20/30，66.67%。
- `LQUnroll+dP16`：24/30，80.00%。

上述结果为历史参考，不直接迁移到本轮 HMMT。

本次计划在 **HMMT February 2026 全部 33 道题**上运行四个固定配置，每题 seed1 生成一次，总计 132 条新轨迹。

任务名称：

`QWEN_GDN_HMMT26_FP_LQ8_HLQ8_LQ16_V1`

本任务授权完成必要的代码审计、最小实现修改、非 HMMT 数值验证、正式推理、评分、统计、故障恢复和报告封存。

无需逐步骤请求人工确认。

但必须遵守科学门禁：如果发现模型实现错误、Hadamard 坐标不一致或评分规则未冻结，不得带着问题启动对应配置的正式生成。

不设置人为的 16 GPUh 上限。资源使用必须如实记录。

禁止根据 HMMT 中途准确率修改量化方法。

## 1. 正式四配置

| ID | 配置名称 | State 精度 | Rotation | Decode Period |
|---|---|---|---|---|
| C0 | `FP_STATE` | FP32 | None | None |
| C1 | `LQUnroll+dP8` | Mixed INT4/INT8 | None | 8 |
| C2 | `H+LQUnroll+dP8` | Mixed INT4/INT8 | H128 Key-side | 8 |
| C3 | `LQUnroll+dP16` | Mixed INT4/INT8 | None | 16 |

正式任务总数：

- 33 道题。
- 4 种配置。
- 1 个 seed。
- 132 条唯一新生成轨迹。

### 1.1 三个量化配置共同约束

必须沿用当前已经完成 AIME26 的 LQUnroll 正式实现：

- 模型：Qwen3.5-9B GDN。
- GDN Layers：24。
- 每层 32 个 State Heads。
- 每个 Head 的 State 为 128×128。
- 24 个 INT4 Heads + 8 个 INT8 Heads。
- Head mask 使用历史冻结版本。
- Key-axis G32。
- Asymmetric Affine Quantization。
- 整数 Zero Point。
- FP16 scale mantissa + optional INT8 exponent。
- Decode Key 使用现有 G32 INT4 编码。
- LeapQuant-style Window Unrolling / Direct Read。
- FP32 Delta Update 缓存。
- FP32 log-decay 缓存。
- 无 Compensator Tokens。
- 无 Residual Smoothing。
- 无新的 Rotation 训练。

C1 和 C3 必须复用此前 AIME26 已验证通过的实际源码，而不是重新实现一个数值行为可能不同的版本。

C2 在 C1 基础上新增固定 H128 Key-side Rotation。

### 1.2 必须保持的因果对照关系

C1 vs C0：

评估 Mixed INT4/INT8 + dP8 相对于 FP32 State 的推理能力损失。

C2 vs C1：

只引入固定 Key-side H128 Rotation。

C3 vs C1：

只改变 `decode_period=8 → 16`。

除了上述预定变化，不允许出现其他算法差异。

本轮不增加 `H+LQUnroll+dP16`，因此不评估 Rotation × Period 的完整交互效应。

- 模型常规激活沿用原模型路径。
- GDN Recurrent State 使用 FP32。
- 不进行 State INT4/INT8 量化。
- 不执行周期性 State QDQ。
- 不启用 K4 更新缓存。
- 不启用 Hadamard。
- 不把 BF16 State 冒充 FP32。
- 不把历史 AIME 的 FP 正确题数直接填入 HMMT。

优先使用此前已经验证过的 native FP_STATE 实现。

C0 必须实际生成新的 33 条 HMMT 轨迹。

## 6. C1 / C3：复用已有 LQUnroll

C1：

`Mixed4/8 + LQUnroll + dP8`

C3：

`Mixed4/8 + LQUnroll + dP16`

复用原有的：

- Packed base。
- Direct Read Kernel。
- K4 编码。
- FP32 Delta Update。
- Boundary Reconstruction。
- Mixed INT4/INT8 量化写回。

不允许退回原 PACE 每 Token 完整 FP32 Replay。

### 6.1 周期边界

dP8：

第 8、16、24……次 Decode Forward 完成更新和输出后，量化写回一次 State。

dP16：

第 16、32、48……次 Decode Forward 完成更新和输出后，量化写回一次 State。

沿用历史 `generated_tokens - 1` 的 Decode Forward 计数语义。

最后一个 sampled EOS 不应错误地作为已经进入 GDN 的 Token。

未满窗口终止时沿用：

`finalize(policy="preserve")`

不能额外量化尾部 State。

## 7. C2：Key-side Hadamard 正确接入

这是本轮唯一需要新增算法代码的配置。

命名：

`H+LQUnroll+dP8`

Hadamard 规格：

- H128。
- 固定正交 Hadamard。
- 无训练参数。
- 不进行可学习 Rotation。
- 不跨 Head 混合。
- 不旋转 Value 维度。
- Head mask 不改变。
- Period 固定为 8。

### 7.1 正确的坐标变换

GDN 的 State 约定：

`S: [B, H, K, V]`

对于 Key-side Hadamard：

`S_rot = H · S`

`k_rot = H · k`

`q_rot = H · q`

真实代码必须检查矩阵乘法方向、维度布局和 decay 的广播方式。

如果原更新为：

`S_t = D_t S_(t-1) + k_t u_t^T`

需要验证当前 GDN 的 `D_t` 与 H 是否可交换。

只有在变换保持递推语义等价的前提下才能直接使用上述坐标映射。

不能把 KDA 的 Value-side Rotation 实现照搬到 GDN。

### 7.2 Prefill 和 Decode 必须一致

Hadamard 必须同时作用于：

- Prefill 对应的 Key 计算路径。
- Decode 的 Key 计算路径。
- Query readout。
- State 持久表示坐标系。
- Direct Read 的基础 State 和更新向量逻辑。

必须特别检查：

- 是否在 K normalization 前或后应用旋转。
- 是否与原 BF16 / FP32 cast 顺序兼容。
- 是否重复旋转 State。
- 是否出现 Prefill Endpoint Double Rotation。
- 是否将已旋转 State 错误地按 Native Basis 解释。
- 是否在每个周期额外发生一次无意义的逆旋转。
- 是否改变原有 K4 编码的分组规则。

### 7.3 State 常驻旋转坐标

建议采用一致的 Resident Key Basis：

整个 Decode 过程中的 Packed Base、缓存 Key 和 Query Readout 都在统一的 Key-side Hadamard 坐标系中。

不要在周期边界不断切换旋转坐标。

### 7.4 Hadamard 验证门禁

正式 HMMT 之前，先进行非 HMMT 数值验证。

第一步：不量化，只使用 FP32 State。

比较 Native FP 与 Key-side Hadamard FP 的 GDN Output、State 坐标变换结果和最终模型输出。

第二步：打开 Mixed INT4/INT8 和 dP8。

比较：

- H+LQUnroll Direct Read。
- 对应旋转坐标系中的 Dense Replay Reference。

至少覆盖 Decode 长度：

`1, 2, 7, 8, 9, 15, 16, 17, 31, 32`

验证：

- Delta Update。
- Query Readout。
- State Boundary Reconstruction。
- Packed INT4/INT8 codes。
- Scale / Zero Point / Exponent。
- Writeback Count。
- Pending Buffer。
- Nonfinite。
- Tensor Shape / dtype。
- Prefill / Decode 连续性。

数值差异应按预先冻结的误差门禁判定，不能为了通过实验随意放宽容差。

若 C2 Hadamard 门禁失败，不得运行 C2 正式 HMMT；已验证的其他独立配置可以继续，但最后必须报告为部分完成，不能制造四配置完整结果。

- 不能因为推理过程中曾出现正确答案就判为正确。
