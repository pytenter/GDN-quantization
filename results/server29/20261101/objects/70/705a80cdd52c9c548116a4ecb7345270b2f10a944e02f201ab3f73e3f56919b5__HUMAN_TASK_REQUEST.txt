### 统一量化位置

审计实际GDN helper的时序：

# 二、统一数学记号

每个Recurrent Head的State：

`X ∈ FP32[128,128]`

第一个维度为Key，第二个维度为Value。

在Hadamard坐标下量化。

沿Key轴，每个Value列分成四个Group32：

`g ∈ {0,1,2,3}`

每组32个Key元素。

原始量化器记作：

`Q32_sym(X)`

默认scale：

`s0[g,j] = amax(abs(X[i,j]), i∈g) / 127`

实际执行必须保留原Canonical的scale floor、舍入、裁剪、negative-zero和解码规则。

新量化器不允许修改位宽、Group Size、零点或Hadamard。

# 三、共享非AIME校准：计算Key行敏感性

三个新方法共用同一份冻结的Key行重要性。

不能为WScale、RowBal、RW分别校准三套不同的重要性。

## 3.1 数据来源

优先复用已有合法的非AIME FP State、Query、Key、Gate及Beta轨迹。

如果已有轨迹不包含计算transported query所需的完整数据，可以进行一次有界的非AIME FP采集。

使用未参与本次最终评测的WikiText-2、PG19等文档。

明确冻结：

- 文档ID。
- Token范围。
- 模型及Runner SHA。
- 采集位置。
- 实际层/Head映射。
- 校准输入顺序。
- CAL/VAL文档划分。

校准与验证必须按文档隔离。

不得使用AIME26题目、Prompt、输出、正确率或历史AIME错误题目进行校准。

## 3.2 计算transpo​rted-query权重

GDN状态更新抽象为：

`X_(t+1) = A_(t+1) @ S_hat_t + B_(t+1)`

其中：

`A_t = alpha_t * (I - beta_t * k_t @ k_t.T)`

在已有Hadamard坐标下，量化误差E_t首先通过下一次更新影响readout：

`delta_o_(t+1) = E_t.T @ A_(t+1).T @ q_(t+1)`

定义：

`g_(t+1) = A_(t+1).T @ q_(t+1)`

计算每个实际Recurrent Head、每个Key行的静态敏感性：

`omega[i] = mean_cal(g_(t+1)[i]^2)`

这借鉴STEPQuant的读取敏感性思想。

必须使用真实GDN Readout Query及正确的Gate、Beta、Key，保持已有H128坐标一致。

Qwen实际16个独立Q/K Head映射到32个Recurrent Heads，但transported query还依赖实际Recurrent Head的状态转移参数。因此不能仅因为Query被共享，就未经核验地把对应omega直接复制。

## 3.3 权重稳定化

omega为静态FP32校准参数，不在AIME期间更新。

为避免极小权重与异常值造成数值失稳：

- 使用冻结的正数floor。
- 在每个32行Group中进行几何均值归一化。
- 使用预冻结的有限上下界进行clamp。
- 保存clamp前后分布。
- 保存Layer/Head/Row身份与SHA。

建议先使用：

`omega_normalized ∈ [1/16,16]`

这是候选算法的数值稳定化规则，不是从论文直接复制的最优阈值。

所有方法使用相同omega。

不得根据AIME结果调整。

# 四、方法W：H+G32+Sym8+WScale

目标：

**让Group32的scale不再仅保护最大绝对值，而是优先降低敏感Key行的量化误差。**

## 4.1 数学定义

当前Group的基础scale为：

`s0 = max_abs(X_group)/127`

设预冻结候选系数集合：

`Lambda = {0.60, 0.75, 0.875, 1.00, 1.125}`

对每个候选：

`s(lambda) = max(lambda*s0, original_scale_floor)`

使用原Sym8舍入和clip得到整数codes并解码。

对Group32计算：

`L(lambda) = sum_i omega[i] * (X[i,j] - X_hat_lambda[i,j])^2`

选择：

`lambda_star = argmin_lambda L(lambda)`

然后将选中的scale、codes与重建值作为当前token真正的QDQ结果。

每个Value列的每个Group独立选择。

如目标相同，使用预冻结的确定性tie-break规则，优先选择更接近lambda=1的候选。

### 重要限制

- omega来自离线非AIME校准。
- X来自当前真实更新后的State。
- 不访问未来Query。
- 不使用FP oracle。
- 不产生额外高精度persistent State。
- 仍然每个Group只需要一个动态FP32 scale。
- zero-point始终为0。

由于候选包含lambda=1，在精确算术下，WScale的当前加权局部重建目标不应差于原absmax候选。

但这不保证完整Readout Error或AIME准确率必然提高。

## 4.2 性能要求

Qwen全部GDN State有大量Group32。

不得使用Python逐Head、逐Group、逐候选循环。

建议使用GPU批处理或融合Triton Kernel：

- 一次载入32个Group元素。
- 同时计算多个候选scale。
- 在GPU上比较加权误差。
- 选择最优候选。
- 输出最终Codes和重建State。
- 不进行逐Group CPU同步。

WScale必须保留在线候选选择语义，不得为提速偷偷替换成另一种离线固定lambda算法。

若实施性能优化，须在非AIME测试上核验输出对应同一冻结公式。

# 五、方法R：H+G32+Sym8+RowBal

目标：

**借鉴STEPQuant和KVarN的尺度归一化思想，使Group内部不同Key行获得不同的有效量化分辨率。**

## 5.1 行尺度

对当前更新后State计算：

`m[i] = sqrt(mean_j(X[i,j]^2) + epsilon)`

在每个Key Group内进行几何均值归一化。

定义：

`r[i] = (m[i]/GM_group(m))^a * (omega[i]/GM_group(omega))^(-b)`

这是一种针对Group32的候选设计，不是原论文公式的完整复现。

选择一套明确的离线超参数：

- a控制Key行幅度。
- b控制读取敏感性。
- epsilon保护近零值。
- r_min/r_max避免极端缩放。

建议使用预冻结的有限候选网格：

`(a,b) ∈ {(0.25,0.25),(0.50,0.25),(0.50,0.50)}`

先在非AIME CAL数据上根据固定的读取误差代理选择一组参数，在独立VAL文档报告泛化表现，然后冻结唯一(a,b)。

RowBal与RW必须共享相同参数，不得分别调优。

建议初始化稳定范围：

`r[i] ∈ [0.25,4.0]`

实际选用的数值必须在正式AIME之前冻结，不得依据AIME正确率修改。

## 5.2 量化定义

先进行行归一化：

`Y[i,j] = X[i,j]/r[i]`

对每个Value列的32元素Group计算：

`s[g,j] = max_abs(Y_group)/127`

执行原Sym8 Encode/Decode：

`q[i,j] = Sym8Encode(Y[i,j],s[g,j])`

最后：

`X_hat[i,j] = r[i]*s[g,j]*q[i,j]`

下一token真正使用的是X_hat。

### 必须满足

- r始终为有限正数。
- 不产生zero-point。
- q仍为Signed INT8。
- 仍沿Key轴G32。
- 不修改GDN更新。
- 本次r根据当前更新后State动态计算。
- 不持久保存未量化的X。
- 动态r所需的工作Tensor不能成为高精度continuation shadow。

### 元数据口径

原Sym32已有每Group的FP32 scale。

RowBal另外引入每Key行的r。

如果将来实现真实packed整数State，必须考虑保存每token最新r或设计等价恢复方式，不能忽略这部分元数据成本。

目前仍采用已QDQ的FP32 State carrier，不声称真实packed INT8显存压缩。

不要额外引入纯Value列缩放后直接套用原absmax，因为该尺度在精确算术下可能完全抵消。

# 六、方法RW：H+G32+Sym8+RowBal+WScale

这是第三个正式候选。

它不是重新发明一套独立量化器，而是严格组合前两个模块。

要求：

- 使用与R完全相同的omega。
- 使用与R完全相同的(a,b)。
- 使用与R完全相同的r计算。
- 使用与W完全相同的Lambda候选集合。
- 使用与W完全相同的加权scale搜索规则。

## 6.1 组合算法

先通过RowBal计算：

`Y[i,j] = X[i,j]/r[i]`

再计算基础尺度：

`s0[g,j] = max_abs(Y_group)/127`

对每个lambda：

`s_lambda = max(lambda*s0,scale_floor)`

`q_lambda = clip(round(Y/s_lambda),-127,127)`

`X_hat_lambda[i,j] = r[i]*s_lambda*q_lambda[i,j]`

**重要：组合方案的scale选择目标必须在原始X空间计算，而不是只计算归一化Y的普通MSE。**

即：

`L_RW(lambda) = sum_i omega[i]*(X[i,j]-X_hat_lambda[i,j])^2`

取最小目标对应的scale进行正式QDQ。

这确保RW仍然优化原始State的加权重建误差，而不是因r的尺度变化改变了目标含义。

## 6.2 消融关系

- W相对原Sym32：只新增WScale。
- R相对原Sym32：只新增RowBal。
- RW相对R：只新增WScale。
- RW相对W：新增RowBal。

此处W、R、RW必须共享相同的量化轴、Hadamard及FP32数值基础。

所有配置使用同一个统一量化器框架，不能分别维护三套容易产生数学漂移的实现。
