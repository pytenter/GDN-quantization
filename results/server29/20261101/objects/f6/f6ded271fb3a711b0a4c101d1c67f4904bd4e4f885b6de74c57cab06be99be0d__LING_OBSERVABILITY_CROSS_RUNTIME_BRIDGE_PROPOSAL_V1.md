# LING_OBSERVABILITY_CROSS_RUNTIME_BRIDGE_PROPOSAL_V1

Status: **PROPOSAL ONLY — NOT RUN AUTHORIZATION**

## Decision problem

Determine, before any formal recovery, whether results produced on the same GPU UUIDs under NVIDIA drivers 580.173.02 and 580.178.04 may be treated as one 32K scientific panel without overwriting or retroactively changing the existing 80 canonical units.

## What is already available

- Frozen scientific inputs, source commits, document and rotation identities.
- Old-driver short numerical reference on GPU6 with exact FP-step, score, target and endpoint fields.
- Old-driver fresh-process exact-repeat evidence on GPU6 and GPU3.
- Old-driver full 32K per-GPU FP reference traces; GPU3 references include bitwise per-chunk replay.
- Eighty old-driver canonical scientific outputs and immutable sidecars.
- A new-driver GPU6 short nonformal probe that matched the short historical reference exactly.

These assets support identity and short/local reproducibility. They do not yet identify full-horizon recurrent-QDQ/Future-KL agreement across drivers.

## Required prospective controls

Before any bridge run, independently review and freeze:

1. exact fixture identities and a result-blind selection rule;
2. same physical GPU UUID pairing for every comparison;
3. runtime, driver, CUDA, package, compiled-kernel and deterministic-flag manifests;
4. compared fields and sampling points across the trajectory;
5. an acceptance rule whose numerical basis is independent of future bridge results;
6. a holdout strategy and immutable evaluator;
7. atomic, append-only outputs that cannot overwrite historical canonical data;
8. an explicit rule for inconclusive or missing old-runtime references.

Any threshold without an independent scientific/numerical basis is `REQUIRES_PREREGISTRATION`. New-driver repeatability alone is never cross-driver agreement.

## Path A — archived-anchor bridge

Use only archived old-driver anchors with complete provenance and rerun matching nonformal fixtures on the same UUID under the new driver.

Minimum useful comparisons should include full 32768-token state-sensitive checkpoints, quantized state hashes or independently justified distance metrics, accumulated RAW/K3/POR quantities, initial pulse identity, FP pairing, and Future-KL. The present archive has strong short anchors and FP-only 32K traces, but does not demonstrably contain all required intermediate quantized and target trajectories for every comparison. Therefore Path A is currently **partially identifiable but insufficient as-is**.

A carefully preselected subset of old canonical scientific identities could be rerun only under a separate authorization as nonformal bridge fixtures, stored outside canonical directories. Selection must be independent of observed effect sizes. Even then, acceptance criteria must be frozen before reruns; this proposal does not specify a numeric tolerance.

## Path B — additional prospective compatibility experiment

This is the smallest potentially discriminating route if a trustworthy old-driver execution environment can be restored without altering the host or historical records.

- Freeze a compact, result-blind factorial fixture covering both GPUs, both documents or representative token fixtures, H and learned L6 rotated paths, both anchors, persistent QDQ, K3/POR and Future-KL through 32768 tokens.
- Execute paired old-driver and new-driver runs on the identical UUID, with at least fresh-process repeats for within-runtime variance.
- Separate two questions: within-runtime determinism and between-runtime agreement.
- Evaluate with a precommitted rule. Exact equality may be proposed only if justified as the intended deterministic contract. Any nonzero tolerance requires independent derivation and user approval before results are observed.
- Keep the bridge dataset outside the 128-unit scientific panel and blind the final evaluator to condition labels where feasible.

If the old driver cannot be recreated with the same compiled/runtime identities, Path B cannot identify driver causality and must return `INCONCLUSIVE`, not PASS.

## Path C — uniform-runtime remeasurement

Create a wholly new 128-unit panel under one frozen new runtime, while preserving the old 80-unit panel as historical evidence. This avoids cross-driver merging and provides the cleanest scientific interpretation, at the cost of rerunning all 128 units and their validation/analysis pipeline. It requires explicit new authorization, fresh premeasurement freeze, independent output namespace and no overwrite of old data.

## Recommendation

First perform a preservation inventory to determine whether Path A has full 32K quantized-state and Future-KL anchors with complete runtime/GPU provenance. If not, choose between:

- Path B, only if the old driver/runtime can be reproduced on the same UUID and acceptance criteria can be preregistered independently; or
- Path C for the strongest panel validity when old-runtime reproduction is unavailable.

No path may start automatically from this proposal. The user must separately approve the chosen design, fixtures, acceptance rule and GPU budget.

## Explicit non-authorizations

This proposal does not authorize rerunning the old 80 units, starting the missing 48, starting a new 128-unit panel, modifying drivers/kernel, changing tolerances, using cross-GPU FP references, or entering L9/AIME/free-generation/Qwen work.
