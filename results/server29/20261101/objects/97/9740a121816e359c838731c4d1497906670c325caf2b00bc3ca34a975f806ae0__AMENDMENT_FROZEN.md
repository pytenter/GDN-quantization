# PROVENANCE_ENGINEERING_AMENDMENT_V2

Prospective engineering-only architecture amendment. Formal measurements before

## Artifact semantics

External file-backed Python/runtime/native code, process executables, model,
tokenizer, configuration, historical snapshots and already-defined scientific
inputs are bound by class, size and SHA256. Stable identities include canonical
path. Process-generated volatile file-backed artifacts are still external: raw
bytes are retained under content SHA256, with original path diagnostic only.
Generated in-memory methods, lambdas, CodeType and wrappers are derived from
closed ingress; they have no independent source-file requirement. There are no
filename, TokenInfo, lambda-name or `<string>` exceptions.

## Startup and independent enforcement

At the child's first controllable point record executable/build, sys.path,
selected environment and all already-loaded file-backed modules. Independently,
a Linux x86-64 ptrace supervisor observes the original executable from exec
onward, including preload/shared libraries before the Python hook. It observes
all tracee threads and children; regular-file read/mmap/exec bytes are checked
at syscall stops before resume. File-backed native maps and mprotect mappings
are checked, including C-level dlopen. No LD_PRELOAD, container, Python-path,
working-directory, runtime rebuild or numerical-kernel change is introduced.

Anonymous generated executable memory is derived only under closed external
ingress. Internet socket creation fails before the syscall. Advisory AF_UNIX
and AF_NETLINK/device/explicit OS query interfaces are separately disclosed;
unknown inherited sockets, stdin/external source, unknown regular files and
unimplemented asynchronous/cross-process ingress fail. This is not a security
sandbox against a malicious frozen runtime or kernel: those are trusted,
identified runtime dependencies. If an actual critical loader bypasses the
observable ingress boundary, the run stops rather than claiming full coverage.

Read-only timezone/locale, account lookup, GPU sysfs/driver queries and Git
administrative identity queries are not counted as independent execution
artifacts. They are explicitly scoped advisory interfaces. Git HEAD and tracked
source state are independently verified by the operational guard; the commit
receipt is phase-specific so the post-commit check is not a self-referential
capsule hash. These exclusions never authorize code loading from those paths:
executable mappings bypass the advisory exemption and require byte closure.

## Discover then enforce

Architecture tests precede the real smoke. V2-A runs only the original fixed
historical development smoke and existing parity paths, with no new scientific
panel. Authorized roots classify actual observed bytes; unknown roots are not
automatically authorized. Immutable candidate receipts are combined only after
all real A runs pass with unknown/unclassified/network zero. The canonical-byte
SHA256 is CAPSULE_MANIFEST_ID. Retained volatile evidence is verified.

V2-B is a fresh process using a read-only frozen manifest. Every observed
external identity must belong to it. New bytes never append, retry or downgrade
to warning. Any escape/hash mismatch/manifest mutation is FAIL_AND_STOP.

## Preservation and scientific scope

Old dirty worktree is read-only input authority; its HEAD, status and all
referenced raw bytes are checked before/after. No code is executed there.
Source scientific bridge and every historical snapshot stay byte-identical.
Only new operational wrappers change output routing, old-STOP guard and
provenance accounting. Model/weights/rotations/quantizer/recurrent semantics,
horizons/JPROP/K3/KL/metrics/thresholds/tolerances/FP policy/docs/panels/seeds and
GPU6 assignment remain unchanged. Cross-hardware FP FAIL is preserved; no FP
reference mixing. The old event-level closure is not used by V2.

Only after targeted real A/freeze/B succeeds may a new local premeasurement
commit be made. From that commit rerun every original blocking gate in fresh
processes; old PASS receipts cannot substitute for new execution. No push.
