# 一、冻结数学实验矩阵

以原生Key坐标的128维归一化Hadamard矩阵H为基线。

定义：

- H：已验证的Key-H128。
- U：Query二阶矩的正交特征向量矩阵。
- P：128维7-bit Bit-Reversal排列。
- Q32：现有已冻结的Symmetric INT8 Group32 QDQ。

实验矩阵：

| ID | R | U | H | P | 正式实验 |
|---|---|---|---|---|---|
| P0 | H | 否 | 是 | 否 | 历史基线，只读 |
| P1 | HP | 否 | 是 | 是 | 新增30题 |
| C1 | UH | 是 | 是 | 否 | 新增30题 |
| S3 | UHP | 是 | 是 | 是 | 新增30题 |

强调：

**C1 = U·H，不是单独U。**

S3是在C1上增加PBR。

P1是在P0上增加PBR。

三种新增配置的量化位宽、Group Size、scale、舍入和persistent QDQ时序必须完全一致。

本任务目标是识别：

1. PBR在H坐标下的效果。
2. U在没有PBR时的效果。
3. PBR在UH坐标下的效果。
4. U和PBR在对称Group32下是否表现出交互。

# 三、统一数学表示：最重要的工程设计

本任务采用两个基础计算坐标：

- H坐标：用于P0、P1。
- A=UH坐标：用于C1、S3。

**P仅属于QDQ内部的Group成员排列，不作为新的长期State坐标。**

这样可以确保：

- P0与P1使用完全相同的Query、Key和GDN更新。
- C1与S3使用完全相同的Query、Key和GDN更新。
- PBR只改变Group32中的元素归属。

## 3.1 P0/P1

设H坐标的更新后State为S_H。

P0：

`S_hat_H = Q32(S_H)`

P1：

`S_hat_H = P @ Q32(P.T @ S_H)`

所有操作均沿Key方向。

先排列Key行，然后执行连续Group32，再逆排列回H坐标。

下一token继续在H坐标下更新。

不能修改P1的Query/Key，也不能额外执行一次Hadamard。

## 3.2 C1/S3

设：

`A = U @ H`

其中U来自原生Key坐标中的Query二阶矩。

A坐标：

`S_A = A.T @ S_native`

`k_A = A.T @ k_native`

`q_A = A.T @ q_native`

C1：

`S_hat_A = Q32(S_A)`

S3：

`S_hat_A = P @ Q32(P.T @ S_A)`

下一token继续在A坐标下更新。

这样S3在数学上对应完整正交变换`U @ H @ P`的Group32量化，但实现中没有额外改变Key/Query的PBR计算路径。

**C1和S3只允许存在PBR量化分组差异。**

不得让C1使用一套U矩阵、S3使用另一套U矩阵。

不得单独为S3重新校准协方差。

# 四、GDN旋转数学等价

在开始实现之前，必须审计当前Qwen GDN源码，核验实际计算图。

按照Key×Value State定义：

`S_t = alpha_t * (I - beta_t k_t k_t.T) @ S_(t-1) + beta_t k_t v_t.T`

`o_t = S_t.T @ q_t`

这里的alpha是Head级标量门控。

对固定正交A：

`S_A = A.T @ S`

`k_A = A.T @ k`

`q_A = A.T @ q`

应满足：

`S_A,t = alpha_t*(I-beta_t*k_A*k_A.T) @ S_A,t-1 + beta_t*k_A*v_t.T`

以及：

`S_A,t.T @ q_A = S_t.T @ q_t`

这是数学等价基础。

但不能仅凭上述公式认定现有融合Kernel的全部操作都满足变换条件。

必须具体审计：

1. Q/K投影。
2. Q/K归一化。
3. Causal Conv。
4. Beta。
5. Head级Gate。
6. Q/K head-sharing和broadcast。
7. Recurrent State shape。
8. GDN读写位置。
9. Token Prefill。
10. Decode。
11. H128原始注入点。

A变换必须作用在**已经完成不满足旋转交换条件的前置操作之后**。

不能随意把稠密U矩阵移动到RMSNorm或Causal Conv之前。

如果实际GDN更新存在非标量Key轴门控或其他会破坏上述协变结构的操作，则必须先分析并证明实际完整算子是否仍等价。

不能为满足研究设计而改变原生GDN数学。

### 从已有H坐标升级到A坐标

已有代码中Query/Key/State可能已经处于H坐标。

此时不能简单再左乘U.T。

应使用正确的复合坐标变换。

给定：

`S_H = H.T @ S_native`

那么：

`S_A = H.T @ U.T @ H @ S_H`

Query与Key使用相同的H→A变换。

实际代码必须依据原Hadamard方向与矩阵布局推导，并通过独立CPU参考核验。

- 数据SHA。
- 模型SHA。
- Query采集位置。
- 校准样本量。
- 层/Head聚合方式。

不要为了提高AIME成绩迭代更换校准语料。

## 5.2 Query的准确位置

必须采集**直接用于GDN State Readout的实际Query**。

不是Q投影层任意一个中间激活。

若当前Runtime的Query已经经过Hadamard，必须根据原变换合同恢复到Native Key坐标后再构造目标U。

如果模型内部存在Key/Query Head共享，需要审计实际映射。

优先按照每个独立Recurrent Head实际消费的Query统计二阶矩，且必须遵循真实Head共享关系。

不能假定Key Head数、Value Head数、Recurrent Head数一一相等。

也不能把全部层和Head无条件混成一套全局U。

## 5.3 未中心化二阶矩

对于某个实际Recurrent State Head，定义：

`Cq = (1/N) * sum_t(q_t @ q_t.T)`

其中q_t是128维列向量。

这里必须采用未中心化二阶矩E[qq.T]，而非默认减去Query均值的样本协方差。

原因是对于固定State误差E：

`E_q ||E.T @ q||² = tr(E.T @ Cq @ E)`

因此Cq直接对应Query读取敏感性。

校准时采用：

- FP64累计。
- 确定性的顺序。
- 真实Query。
- 合法且足够多的样本。
- finite检查。
- Symmetry检查。
- 特征值非负性检查及数值舍入审计。

不要将时间相关的Query样本简单称为独立同分布样本。

不需要保存所有token的完整Query大Tensor；可以采用流式累计并保存必要的可审计统计和样本身份。

## 5.4 特征分解

使用CPU FP64：

`Cq = U @ diag(lambda) @ U.T`

要求：

- 特征值降序排列。
- 128×128完整正交特征基。
- Orthogonality residual。
- Eigendecomposition residual。
- Eigenvalue spectrum。
- Condition/degeneracy诊断。
- FP32部署矩阵数值检查。
- 每个实际Head的U和SHA。

必须特别处理Eigenvector符号不唯一性。

采用冻结的确定性符号规范，例如每个特征向量绝对值最大分量取非负。

近重根或者完全重根时，应显式检测并采用固定的、可复现的子空间选基规则。

不能根据AIME结果选择符号或重排特征向量。

若无法可靠建立同一U，应fail-closed，而不是随机产生不同Rotation。

## 5.5 C1和S3共享同一U

将所有U矩阵及校准身份封存。

C1和S3必须加载同一份U。

不得重新计算或分别拟合。

U属于离线静态旋转，不依赖推理时的当前Token或FP oracle。

# 六、Hadamard、PBR及对称Group32数学资格

## 6.1 Hadamard

使用原H128数值合同。

不重新生成另一套Hadamard。

保留：

- 原H矩阵身份。
- 归一化方式。
- 符号模式。
- FP计算实现。
- 模型坐标位置。

如果需要由显式矩阵乘法替换FWHT，应先验证与现有H128数值合同的差异，并在正式前冻结。

不能为了S3改变P0既有行为。

## 6.2 Bit-Reversal

128维需要7-bit索引反转。

定义：

`p(i) = reverse_bits(i, width=7)`

例如：

- p(0)=0
- p(1)=64
- p(2)=32
- p(3)=96
- p(4)=16
- p(5)=80

要求：

- p是0到127的双射。
- P.T@P=I。
- PBR实现方向明确。
- 对P和P.T的使用与数学公式一致。
- 不跨Layer。
- 不跨Head。
- 不跨Value列。

本次Group32每128个Key元素分为4个连续组。

PBR必须改变哪些Key通道归属同一个Group。

如果排列只在同一Group内部改变顺序，那不能作为有效PBR处理。

## 6.3 冻结对称量化器

Q32使用原Canonically qualified Symmetric INT8 Group32。

- INT8 signed codes。
- FP32 scale。
- 原scale floor。
- 原CUDA reciprocal/division语义。
- 原rounding。
- 原clip。
- 原negative-zero flags。
- 原State dtype和writeback时机。

不修改Codec本身。

P1/C1/S3只能改变规定的正交坐标及排列。

量化器实际按Key轴，每Value列4组。

不得使用：

- Group64/128。
- Asymmetric zero-point。
- FP16 scale。
- 2D tile。
- Dual-M row/column scaling。

# 七、关键数学负控

正式AIME前必须执行：

### Test A：Identity P

P1的P=I时应复现P0的Codec计算。

S3的P=I时应复现C1的Codec计算。

### Test B：Identity U

C1的U=I时应复现P0。

S3的U=I时应复现P1。

这里要求的是相应数学合同的复现，不得在真正的U校准任务中将U固定成I。

### Test C：Group128 Permutation Invariance

临时Codec-only数学测试中：

`P @ Q128(P.T @ X)`

应与：

`Q128(X)`

在明确的对称量化数值合同下等价。

用独立参考检查数值和负零处理。

Group128仅用于负控，绝不是新增正式AIME配置。

### Test D：FP Rotation Equivalence

取消INT8 QDQ。

比较原生FP模型与A=UH旋转FP模型：

- GDN State。
- Query。
- Key。
- Readout。
- Layer outputs。
- Full-model logits。
- 多token状态递推。

必须使用相同冻结输入。

预先以原有FP路径数值噪声和独立FP64参考为依据冻结容差。

不要求不同GPU浮点计算图逐字节一致，但不得在AIME结果出现之后调整阈值。

### Test E：C1/S3相同FP递归

在无量化时，C1/S3使用相同的A坐标、相同Q/K、相同FP State。

两者输出必须满足相同数学模型和既定数值资格。

这可以直接证明PBR没有错误地改变原生GDN递归。

### Test F：旋转后协方差对角

设：

`Cq = U diag(lambda) U.T`

C1的A=UH。

验证：

`A.T @ Cq @ A = H.T @ diag(lambda) @ H`

其对角线理论上等于：

`trace(Cq)/128`

S3的PBR只能改变相应通道顺序，不能改变该对角均匀性。

这一性质属于Query二阶矩对角敏感性均衡，不代表完整Readout Error必然下降。
