# Qwen3.5-9B：STEPQuant vs Hadamard+Dual-M AIME26 正式评测

你现在是我的 Qwen/GDN recurrent-state quantization 科研执行 Agent。

本任务暂时停止新旋转训练，优先回答一个真正的端到端科学问题：

**在同一个Qwen3.5-9B模型、同一套AIME26两seed采样协议下，完整STEPQuant@6与Hadamard+Dual-M的数学推理准确率分别是多少？**

不要使用Future-KL推测AIME表现，必须真实运行完整生成和Frozen V4评分。

## 2. Method A：完整STEPQuant@6

官方参考：

https://github.com/Dreamer-Toby/STEPQuant

固定官方源码commit、校准代码和量化算法定义。

STEPQuant@6是论文完整的名义6-bit方法，包括：

- Temporal lifetime-aware precision allocation
- Mixed precision map
- FP16 pivot protection
- Key-row-aware weighted dual-axis fitting
- Value-column scale fitting
- Persistent quantized-state writeback

这是外部论文基线，不符合我们自己方法的全INT8限制；必须独立标识其真实bit配置与metadata成本。

禁止将all8、w=1、pivots=0的Dual-M消融冒称为完整STEPQuant。

官方论文主要使用Qwen3.8-27B，本任务必须重新确认其在Qwen3.5-9B上的兼容性。

只复用官方STEPQuant的数学与Codec算法，运行时尽量接入本项目已有的可信Qwen HF/manual forward。

禁止因为官方使用SGLang，就静默将本项目切换成SGLang推理。

不得直接使用官方HF参考路径中仅支持greedy的生成函数执行正式评测。必须使用冻结的两seed随机采样器。

若需要大规模重写GDN recurrence kernel才能实现完整STEPQuant，应STOP并报告，不允许无限移植。

### STEPQuant校准

在AIME26之外使用合法校准数据。

优先复用官方论文对应的WikiText校准协议、row impact、lifetime、pivot与bit allocation规则。

必须记录：
- Calibration数据与token SHA
- 官方代码commit
- Calibration配置
- Gamma与impact定义
- Lifetime horizon
- Precision map
- Pivot mask
- 每层每head位宽
- Scale dtype
- 完整Plan SHA

不能直接复用Qwen3.8-27B的precision map。

不能使用AIME26题目、答案或正式生成结果做校准或选择超参数。

如果无法得到真正符合官方定义的Qwen3.5-9B STEPQuant@6 Plan：

`STEPQUANT_PLAN_QUALIFICATION = FAIL`

停止正式生成，不能以另一个简化Codec替代。

## 3. Method B：Hadamard + Dual-M

复用以下已资格科学资产：

`QWEN_GDN_DUAL_AXIS_PROSPECTIVE_REPLICATION_5DOC_V1`

以及

`QWEN_GDN_C6R_DUAL_M_INTERACTION_REUSE_5DOC_V1`

本条件固定：

```text
ROTATION = HADAMARD_H128
BITWIDTH = INT8
IMPACT_WEIGHT = 1
PIVOTS = 0

ROW_SCALE = FP16
COLUMN_SCALE = FP16

CODEC = ORIGINAL_QUALIFIED_DUAL_M
```

完整保留原column LS、final re-encode、scale floor、clipping和rounding定义。

不得使用C6R、C7或新训练的旋转。

不得增加Dual-W、mixed bits、NoScaleInflation或其他干预。

必须验证Key-side Hadamard坐标、GDN读写路径与此前合格的H+Dual-M实现一致。

不得因为AIME结果不理想而修改Codec。

## 4. 同一运行时与真实persistent QDQ

两种方法必须使用：

- 相同Qwen模型权重
- 相同tokenizer
- 相同BF16权重dtype
- 相同非量化模型层
- 相同prompt
- 相同随机采样器
- 相同EOS和长度规则
- 相同评分器

只允许各方法定义本身带来的rotation、codec、bit allocation和pivot差异。

必须核验两组在原生GDN计算路径上的接入边界。

不能让STEPQuant使用一种不同的未量化GDN递归数学实现，却把所得差异全部归因于量化器。

特别检查prefill完成后的首个量化状态及后续每token写回时序。

每一次量化状态更新后，下一token必须使用该方法真实保存的状态表示。

不得让任何方法通过未量化的persistent FP32 state跳过量化误差反馈。

对于STEPQuant，允许官方定义中的FP16 pivot；对于Hadamard+Dual-M，禁止高精度pivot或补偿缓冲。

如果两种方法使用不同物理state表示，必须分别报告实际存储语义。

不能把FP32 tensor承载QDQ值称作physical packed INT8。

尤其要避免以下错误：

- 以greedy输出冒充seed1/seed2采样。

- 中途偷偷恢复FP recurrent state。
- H+Dual-M不执行实际旋转。
- STEPQuant校准Plan与9B模型不匹配。
- 只运行短上下文就推断81920 token一定可运行。

首先测真实生成吞吐、内存增长和长上下文KV cache开销。

`RESOURCE_OR_RUNTIME_STOP`

## 8. Frozen V4评分

所有120条完整生成后进行独立评分。

必须调用历史Frozen V4的正式答案提取与评分逻辑，包括原有的最终主张、暂定结论、撤回及重述处理规则。

不得仅根据最后一个数字或`\boxed{}`字符串另写一套简单评分器。

对每种方法输出：

```text

seed2_correct / 30
total_correct / 60
accuracy_percent
```

同时输出：
- 每题两个seed的正确性
- 两方法配对胜负
- 正确性分歧数量

- EOS与长度截断数量
- 无法提取答案数量

主要指标：

`Accuracy_STEPQuant6 - Accuracy_H_DualM`
