==================================================
七、Gate A：真实Hadamard FP state测试
==================================================

这是本任务第一项科学性探索。

先通过经验证的Qwen full-model FP路径构建Hadamard坐标下的真实FP recurrent state。

要求：

1. Hadamard只施加一次。
2. 作用于经确认的Key坐标系。
3. 与正式量化模型保持相同q/k旋转定义。
4. Value侧及下游计算保持不变。
5. 不允许直接将native FP缓存随意乘H并假定等价。
6. 必须核对FP Hadamard与native FP在已冻结容差下的功能等价性。
7. 若跨进程数值不稳定或正式kernel资格不足，则STOP。

对于真实FP state，记录：

- document ID
- layer
- head
- token position
- state shape/dtype
- 原始状态hash
- 旋转坐标身份
- 原始状态绝对最大值
- row mean-abs分布
- column mean-abs分布
- row imbalance指标
- outlier指标
- state RMS/范数
- 非有限值统计

推荐位置：
token 1、8、32、128。

如果只完成部分位置，必须准确披露，不得补造。

对同一个FP snapshot离线施加A/B/C/D，不改变model recurrent轨迹。

报告：
- State relative MSE
- absolute MSE
- p99 absolute error
- max absolute error
- zero-code fraction
- saturation fraction
- actual rounded-clamp fraction
- unrounded level >127 fraction
- FP16 scale floor/ceiling触发
- 有效量化步长分布
- 按layer/head划分的paired delta

D的有效step：
s_eff[i,j] = r[i] * c[j]

不能直接拿D的row scale与A的column scale做一一大小比较。

特别验证：
真实Hadamard state的row imbalance程度，是否与CPU合成案例具有可比性。

但是这种相似性只能是描述性观察。

不能根据这一批真实state重新调整D的scale参数。

数值安全门禁：

- 非有限输入或重构直接FAIL
- 有效非零数据落入严重FP16 scale floor/ceiling失真区域时按预注册阈值STOP
- decode roundtrip不一致直接FAIL
- 未经量化的完整FP缓存跨token保留直接FAIL
- 无法区分scale量化和clipping影响时标记NOT_IDENTIFIABLE

若D的局部MSE比A更低，只能报告：
REAL_FP_SNAPSHOT_LOCAL_RECONSTRUCTION_IMPROVED

不得报告长期Future-KL改善。

如果D退化，也必须保留完整结果。
