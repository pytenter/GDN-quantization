CPU_CONTROL_REVISION_01 — CPU-only future control correction

Status: PREPARED_NOT_DEPLOYED_GPU_NOT_AUTHORIZED. This revision changes only
prospective device admission and ownership evidence. No GPU, NVML, actual driver
load, cuInit, model forward or benchmark was executed during its preparation.
The original 407-source freeze and original sealed CPU delivery remain unchanged.
Parent-owned overlay/addendum and separate delivery are required before these
copies can be used in any separately human-authorized future GPU qualification.

The controller rejects an owned worker PID appearing on any unauthorized UUID.
During startup, the controller may observe no own GPU record while CPU hashes
and model initialization are pending. The worker PRE/POST gates require nonempty
actual own-PID records, all on the authorized UUID, and preserve full success or
failure observations. Existing foreign jobs on other cards are allowed; foreign
jobs on the selected card reject admission. Cleanup signals only the exact owned
PID/starttick/cmdline and waits until that PID disappears from all UUIDs. It never
marks release just because the PID disappeared from the selected UUID.

A separate Driver ordinal gate runs after the existing permit and before the
Torch import and all seed/model/benchmark calls. It hashes the unique frozen resolved
libcuda.so file, opens only that exact path, and uses cuInit(0), cuDeviceGetCount,
cuDeviceGet(0), and cuDeviceGetUuid_v2 (falling back only when the v2 symbol is
absent). It requires CVD exactly0, exactly one visible device and the precise
expected UUID. Failure retains API return codes and observed identity before
model allocation. No context creation, primary-context retain, context switch,
memory allocation or kernel API is requested by this gate. Driver enumeration
alone is not proof of the later runtime allocation, so NVML own-PID and actual
library PRE/POST gates remain required. Its real outcome remains NOT_RUN.

The [CUDA 12.1 Driver initialization reference](https://docs.nvidia.com/cuda/archive/12.1.1/cuda-driver-api/group__CUDA__INITIALIZE.html)
defines cuInit as Driver API initialization. The
[device API reference](https://docs.nvidia.com/cuda/archive/12.1.1/cuda-driver-api/group__CUDA__DEVICE.html)
describes ordinal handles and UUID queries. The
[CUDA environment documentation](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/environment-variables.html)
describes visibility and enumeration. This revision conservatively validates
count==1 and the actual UUID instead of assuming that a particular driver's
ordinal filtering is correct. Unexpected enumeration fails closed; no real
Driver/CVD behavior was tested during this CPU-only task.
