# PROVENANCE_EXECUTION_CAPSULE_V3 — unqualified candidate

V3 replaces runtime-wide regular-file ingress classification with explicit
source, scientific-asset, environment, executable and shared-library identities.
Ordinary OS data-file reads are not traced or classified. No claim of
`NO_EXTERNAL_FILES_READ` is made.

The 125-file historical source bank is a byte-identical candidate superset,
not a claim that all 125 files execute. Source/extension loader events, AST
helper receipts and module origins identify the actual executed closure during
qualification. Historical code remains unchanged; the adapter replaces only
operational paths, the Git-based guard and provenance observers. Numerical
functions, documents, rotations, tolerances and every-token INT8 writeback remain
unchanged. No V1/V2 source or receipt is edited.

The 3090 execution worktree is an exact clean **sparse** checkout of this branch,
with `provenance_capsule_v3` present and the same committed source bytes. It is
not represented as a full-history/full-repository checkout. Historical parents
remain read-only external assets, never the measurement execution directory.

Only generated run outputs and detached launch/STOP/report receipts are ignored
by Git in this new namespace; source and input manifests remain tracked. The
unqualified scaffolding commits are neither qualification nor premeasurement
commits. Formal Discovery remains prohibited until G1–G10, qualification freeze,
scientific premeasurement freeze and post-commit gates have all passed.

The observer is scientific reproducibility instrumentation, not a hostile-code
sandbox. Python loader origins and experiment-level subprocess launches are
checked; loaded native libraries are checked against explicit identities.
No general `open()`/locale/gettext/OS metadata classifier is installed.
