# H+Dual-M 身份与 HF/manual 接入审查

本文件为 CPU/只读源码审查。没有运行本次 GPU canary 或正式生成；`H_DUAL_M_IDENTITY.json` 绑定了实际原路径、SHA、十五个小文件快照和历史回执。不使用已 STOP 的训练 readiness adapter，不改变旧资产。

## 可信数学来源

权威历史根为 `/data/zypan/analyses/qwen_gdn_dual_axis_prospective_replication_5doc_v1/experiments/qwen_gdn/quantizer/QWEN_GDN_DUAL_AXIS_PROSPECTIVE_REPLICATION_5DOC_V1`。其冻结 manifest、实际文件和后续 C6R interaction 任务复制的三个公共科学源相同：

|源|SHA256|
|---|---|
|`src/core.py`|`aa338b8b83cde62b97c94fd205d1c62999f783e7ec3242cbb813dc877e01f575`|
|`src/worker.py`|`e04ec85092ee4f2207699366b2aaa61e1e71038e728c9234477b5b2c21794773`|
|`src/codec.py`|`ece859b901145c6d9d646b8befd01916037c9117ef4a80f7b801f27f79f8c23f`|

H 来源为原 `formal_c128_runner.py` 的 `QwenKeyHadamardPatch`，不是 `QwenFrozenRotationPatch`。原 `_transform` 在收到 `use_qk_l2norm_in_kernel=True` 时先执行原 normalize_qk，分别对 q、k 执行 FP32 `@ H128`；H 是 canonical 递归构造并除 sqrt(128) 的矩阵。value 不旋转；core 关闭重复的 q/k normalization，readout 转回原 value dtype。没有 Delta/C6R/C7。冻结 core 的 H memoization 只复用相同矩阵数值，原资格曾比较 reference 与执行器 128-token bytes。

状态为 `[B,H,K,V]=[1,32,128,128]`，K 是旋转轴。q/k 已在模型原代码中扩展为32 value heads；原 recurrence 自然构建 H key 坐标下的 state，不额外旋转 value 轴或 out_proj。当前 readout 仍在本次 state QDQ 前产生，不能以 QDQ 后 state 重新计算当前 readout/logits。

Dual-M 实际调用冻结 `codec.encode(...,'DUAL_M_INT8')`。其 encode 从 inherited CPU codec 提取 unchanged AST：

1. FP32 source；row scale=`safe_half(sqrt(clamp_min(mean(abs(x), V),1e-20)))`。
2. 用 FP16 row scale 的 FP32 值归一化；初始 column scale 来自归一化绝对值/127 的 K 轴最大值。
3. 原 torch.round ties-to-even、clamp[-127,127] 编码。
4. 固定一次 column LS，用 `v=row*z` 的原分子/分母、原零分母 fallback、safe_half。
5. 用更新后的 column scale 作 final re-encode。
6. 保持 `(rows.float()*columns.float())*codes.float()` 的原 decode 乘法结合次序。

`safe_half` 保留 LOW=`2**-24`、HIGH=`65504`、FP16 转换及 NaN 检查。没有 pivots、importance 权重不是校准统计而是1、没有 mixed bits 或额外干预。上述文字仅解释已冻结代码，不作为另一套算法实现。

原 `worker.dual` 将24层按 batch 维拼接，调用原 codec，逐层 `state.copy_(decoded)`；历史 canary 比较了整批与逐层 codes/scales/reconstruction 的原始字节，并与官方 all8/ones/no-pivots fit_state 做 exact 比较。**此历史 Dual-M 消融绝不能标为完整 STEPQuant@6。**

原安全检查也必须保留：对 FP16 raw row/column scale 越界涉及的非零 state 元素，逐 layer/head 计算 affected energy fraction 与 affected relative MSE；两者分别达到 `>=1e-4` 和 `>1e-2` 时 STOP。较小 floor 事件仍要记录；不能把未 STOP 写成没有 floor。输入、输出及保存尺度必须有限，尺度为正。

## Persistent writeback 的历史证据及本次新增合同

旧 `worker.py:163–170` 在每个输入 token 原 HF forward 后调用 QDQ 并写回；`Observe:69–74` 核验下一 GDN kernel 的 initial_state 使用上次写回的 storage，并在规定点核验 bytes。每 token 每层原 GDN core 调用恰一次。四张固定3090的 initial/fresh128-token资格和 cross-GPU128 exact 均有真实 PASS，五条 H+Dual-M 32K 轨迹已完成。历史物理 packed INT8仍为 NOT_QUALIFIED，native/H 全模型数值等价失败记录仍保留。

旧五文档是逐 token streaming，包含 prompt-like 文本的每个 token 都经历 QDQ。旧 AIME Canonical60 则是整个 prompt 一次 HF prefill，直接采样首 token，首个 decode 后才 QDQ；其 `quantizer_audit.prefill_quantized=false`。二者历史不同，不得声称相同。

本次由协调器明确冻结的新合同为：

```text
同一 HF batched prompt prefill
→ 立即以该方法 codec QDQ 全24层 state
→ 原冻结 sample_next 采样首token（不重算当前logits）
→ 每次 HF 单token decode forward
→ 该方法 QDQ 全24state
→ 原 sample_next
```

两方法都 `prefill_quantized=true`；prompt 内部不逐 token QDQ。这是本次需要新 canary 验证的接入合同，不可借用旧 streaming canary 假称该合同已 PASS。历史 AIME52/41/40等只作参考，不能自动成为严格相同量化时序的对照。

若合法输出含 n 个 generated tokens，最后一个 token在EOS/长度停止时不再被额外送入下一次 model forward，则应有：

- n 次每方法 QDQ（1次prefill和n−1次decode），24n 次 layer writeback。
- 24(n−1) 次 next-kernel consumption checks；首 decode 必须消费 prefill QDQ。
- H helper调用24n次；chunk prefill24次、recurrent decode24(n−1)次。

每条请求必须重新创建 cache 和 torch.Generator(seed)，清除上个方法/请求的 hooks 与临时状态；异常同样移除 hooks。禁止输出后根据正确性重采样。

## 单一最小 runtime 接入建议

不复制32K worker的完整 token loop/评分/checkpoint机制，也不导入训练 STE。复用原正式 sampler、chat template、EOS、top-k tie audit、presence penalty 和 token generator；只增加两个清楚的接口：

```text
method_context(model)             # H:原QwenKeyHadamardPatch；STEP:其方法本身所需配置
post_forward_qdq(cache, phase)    # 原codec + 原安全检查 + 原state写回
```

H 的 `post_forward_qdq` 可提取冻结 `worker.dual` body，用新任务的 K.save/CURRENT、same state getter及codec绑定；仅改任务I/O，不重写量化公式。正式 trace/metrics 开关可沿原接口使用；汇总已有安全标量即可，不必保存80K步的全词表logits或三十二K科学评分产物。

STEP侧已找到官方 `StateCodec(QuantizationPlan(...)).encode/decode`；完整6-bit Plan必须另行合格。不要使用官方 greedy generator 或替换该项目 GDN recurrence/cache 数学。两臂的非量化 qmod body、dtype、conv/attention及数学数值绑定必须相同。

原 H runtime 是 `core.load()` 的同一 BF16模型、原 recurrent helper，并只把 chunk g.cumsum 绑定到已资格 compensated 路线。若继承此 H 数值路径，应把**同一个 chunk 绑定与运行 flags用于两臂**，不要只给STEP使用另一条未量化运算路径。原 AIME历史 hard-deterministic flags为false，而旧H资格为true；本次选择必须在共同 runtime里明确冻结并披露差异。不能仅凭函数名字证明实际 FLA/hub dispatch一致，应核验实际绑定/环境，不自动安装改变后端的依赖。

128-token资格应分别验证：冻结 H/reference逐值与逐字节、完整STEP codec parity、新的batched-prefill边界、下一kernel消费、同seed fresh-process重复、真实seed1/2 RNG状态与采样器、四GPU相同源/Plan环境。旧 native/FP_H 数值等价曾因 token1 relL2约.00671846超旧.002而失败；该历史不得改写为PASS。H参考parity与native/H等价是两项不同命题。

## 81920长度的真实依据与风险

模型配置包含8个full-attention层、4个KV heads、head_dim256、BF16 KV。以batch1且不量化KV估计：

```text
KV_bytes(N) = 2(K,V) * 8 * 4 * 256 * 2(BF16 bytes) * N
            = 32768 * N
```

81920个输出位置为2.5GiB；加上历史最长373-token prompt，N=82293约2.51138GiB。32768位置为1GiB，长生成比32K多约1.5GiB。24层 FP32 recurrent state固定50,331,648B（48MiB），不会随上下文线性增大；conv state也为固定规模。

存在真实同模型、同 manual HF、同GPU0的完整81920历史生成：`Canonical60/raw/c6r/aime26_17_seed1.json`，SHA `b601139ee8f5d76649fe9dba6bd0ef5af3723bbbe0cedad33a94f9b2373b3cc7`，373 prompt，81920输出，finish=length，runtime_error=null、nonfinite=false，peak allocated `19874.63134765625 MiB`（约19.409GiB），latency `10406.006662607193s`。其 C128 QDQ calls=81919、prefillfalse。该记录证明共同旧HF/cache确曾支撑81920，不证明本次两个新 codec/runtime 已合格，也不证明reserved/NVML峰值或所有GPU均相同。

需要新增实测的成本包括：Dual-M/完整STEP编码临时tensor、FP16 pivots与metadata、cache增长时的旧新allocation并存、allocator碎片、完整Plan的每层/每head差异。理论KV和历史长记录不能替代本次安全资格。不得通过减小81920、改sampling、SGLang或新kernel绕过OOM。资格前本次81920资源状态仍为 **PENDING_MEASUREMENT**。

本次runtime若把codec解码结果写回原FP32 cache，应如实报告 **FP32 tensor carrying QDQ values**。H理论code payload为12MiB、FP16 row/column合计.375MiB，但原驻留cache仍为48MiB；不能称physical packed INT8。STEP `PackedState` 有4/6/8-bit与pivot打包能力，若同时保留FP32载体也不能据此宣称runtime只驻留packed state。两者实际持久和瞬时表示分别记录。

所有新 GPU资格、正式生成及资源账本由根协调器统一授权/dispatch；本审计没有启动任何GPU。
