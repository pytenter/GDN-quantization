## 2. 严格科学边界

不可妥协：

1. 所有recurrent-state数值元素固定为signed INT8，范围[-127,127]。
2. 不允许mixed-bit。
3. 不允许FP16 pivots。
4. 不允许FP16/FP32 persistent compensation state。
5. 不允许LeapQuant式延迟requantization。
6. 不允许跳过任意token的QDQ/writeback。
7. 不允许更改Hadamard矩阵或训练新的旋转。
8. 不允许修改模型参数。
9. 不允许引入Qwen SGLang作为新runtime。
10. 不允许改变现有正式实验结果。

区分两种概念：

- Persistent INT8-QDQ/writeback semantics
- Physical resident INT8 storage

FP32 tensor中存放已经QDQ的数值，仅满足前者，不满足后者。

新codec允许使用FP16 scale元数据，但必须报告其真实存储字节数，不能把它当成零成本，也不能保留完整FP状态矩阵。

本轮CPU codec可以使用瞬时FP32计算进行fit/decode，但encoded state对象只能拥有INT8 codes和被允许的scale元数据，不得额外保存原始完整FP状态。

## 3. 本轮四个候选条件

统一使用状态形状：

S: [B, H, K, V]

Qwen GDN通常K=128、V=128，但应从实际代码审计确认，不要硬编码非必要维度。

所有新codec均应用在已有Hadamard坐标系下的recurrent state，不能重复旋转，也不能改动Value侧计算。

### A. C128_CANONICAL

调用现有冻结的Qwen C128参考实现。

公式：

s_j = max_i |S_ij| / 127

z_ij = clamp(round(S_ij / s_j), -127, 127)

S_hat_ij = s_j * z_ij

必须沿用现有实现的epsilon、dtype、rounding及运算顺序。

这是绝对基线，不允许重写后直接宣称等价。

### B. C128_FP16_SCALE

在保持单轴C128结构的情况下，只改变scale元数据的存储精度为FP16。

要求：
- 使用有明确下界的安全scale转换
- 基于真实存储后的scale重新编码
- 独立报告与CANONICAL的差异
- 不允许把本条件当成原冻结C128

目的：隔离scale精度造成的影响。

### C. C128_LS_FP16

只使用column scale，不引入row scale。

过程：
1. 计算初始column scale。
2. 将scale转换为真实FP16存储值。
3. 得到初始INT8 codes。
4. 固定codes进行一次column least-squares更新：

   c_j = sum_i(z_ij*S_ij) / sum_i(z_ij^2)

5. 处理分母为零及非法scale。
6. 量化并存储最终FP16 scale。
7. 根据最终scale重新编码INT8 codes。
8. 从codes+scale进行重构。

该条件是我们自定义的单轴拟合消融，不要声称它就是STEPQuant论文中的独立方法。

目的：区分“最小二乘拟合”与“额外row-scale自由度”。

### D. DUAL_M_INT8

核心候选：STEPQuant Spatial的w=1消融。

全部state元素固定8-bit，不使用Temporal allocation和pivots。

使用：

m_i = mean_j |S_ij|

r_i = sqrt(max(m_i, 1e-20))

将r_i转换为真实存储的FP16 scale，并使用转换后的值进行后续计算。

初始化column scale：

c_j^(0) = max_i |S_ij / r_i| / 127

转换为安全FP16 scale。

初次编码：

z_ij = clamp(round(S_ij/(r_i*c_j^(0))), -127, 127)

随后固定初次codes，进行一次column least-squares拟合：

v_ij = r_i*z_ij

c_j^(1) = sum_i(v_ij*S_ij) / sum_i(v_ij^2)

必须妥善处理零分母，遵守STEPQuant参考实现的fallback。

将最终c_j^(1)转换为实际FP16存储值，然后重新编码：

z_ij^(final) =
clamp(round(S_ij/(r_i*c_j^(1))), -127,127)

最终：

S_hat_ij = r_i*c_j^(1)*z_ij^(final)

注意：
- 重构只允许读取最终INT8 codes和FP16 scales。
- 不允许直接将拟合过程的浮点reconstruction当成持久状态。
- 拟合时必须使用实际存储精度的scale。
- 禁止额外反复迭代到更低MSE。
- 必须记录所采用的STEPQuant数值下界。
- 不允许启用STEPQuant的INT2特殊分组逻辑。
- 不允许使用动态Query importance。
- 不允许使用历史文档的评分结果挑选最有利的codec参数。

如果与官方all-INT8、impact=ones的fit_state实现存在差异，必须解释并通过独立reference parity测试，不能自行认定等价。

### Gate 2：Dual-Axis reference parity

如果能取得固定commit的STEPQuant实现：

构造：
- architecture = "gdn"
- bits = 全8
- impact = 全ones
- pivots = 0

- code identity
- FP16 row scale identity
- FP16 column scale identity
- decode reconstruction
- shape、dtype和范围

如存在因明确浮点运算顺序导致的微小差异，必须在观察实验结果前给出固定容差及逐项原因；禁止为了PASS事后扩大阈值。

### Gate 3：Roundtrip与存储

为新codec提供清晰的encode/decode接口。

测试：
- z dtype必须为torch.int8或明确等价的8-bit packed code表示
- codes范围[-127,127]
- row/column scales shape正确
- scales有限且为正
- decode(encode(S))与编码阶段最终reconstruction一致
- roundtrip不依赖未存储的S
- B>1及多head正确
- 非法shape直接拒绝
- NaN/Inf输入直接拒绝或明确fail-closed
- scale underflow、overflow及全零情况有确定行为
- fresh-process CPU deterministic重复测试

任何失败都要保留最小反例。

不要将临时浮点codes当成物理INT8 storage。

### Gate 4：数值对照

在完全相同的合成状态面板上，运行四种codec。

报告：
- State relative MSE
- absolute MSE
- max absolute error
- p99 absolute error
- zero-code fraction
- saturation fraction
- overflow/clipping proxy
- row/column scale分布
- 各条件最小、最大scale
- encode/decode CPU latency（描述性）
- codes和scales的实际byte数

对没有row scale的条件，标记N/A。

比较：
- C128_CANONICAL vs C128_FP16_SCALE
- C128_FP16_SCALE vs C128_LS_FP16
- C128_LS_FP16 vs DUAL_M_INT8
- C128_CANONICAL vs DUAL_M_INT8

这些比较不能自动解读为长期效果。

禁止通过挑选某个outlier分布来声称总体方法获胜。

所有测试面板的生成参数、seed和输入hash必须保存。

### Gate 5：零GPU的recurrent语义测试

用小型合成recurrent更新模拟连续QDQ/writeback。

每个step都执行：
decode stored INT8 state
-> FP32 transient state update
-> encode to INT8
-> discard transient full state

下一step必须只从上一step的encoded state恢复。

测试至少：
- 1 step
- 8 steps
- 32 steps
- 128 steps

禁止跨step保存未经QDQ的完整FP state。

注意：此测试只证明codec接口具备recurrent semantics，不证明Qwen正式GDN full-model parity。

必须将正式runtime QDQ timing、cache integration和完整模型FP equivalence标为GPU资格阶段待验证，不能在Phase 0提前宣称PASS。
