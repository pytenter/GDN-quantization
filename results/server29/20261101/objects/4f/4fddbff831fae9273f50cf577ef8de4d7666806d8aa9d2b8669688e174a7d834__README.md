# PACE-4/8 AIME26 seed1, R2 versus R3

This independent execution implements R2 (`decode_period=8`) and R3
(`decode_period=1`) over the same original canonical30 prompts, seed1 and
FrozenV4 scoring. Only server55 physicalGPU0 is authorized. Server29 is a CPU
archive destination; its GPUs5/6 belong to other users.

The source implements packed UINT4/UINT8 state payloads, packed integer zero
points and FP16 scales, with fixed-value-column/key-axis groups of32. Each
layer uses24 INT4 and8 INT8 heads. A single non-AIME calibration over8 independent
2048-token windows selects both arms' identical mask by `e/(1-a**16)`.

Production keeps the packed base and a bounded buffer of decode INT4 keys,
BF16 raw values/beta and FP32 log-decay. Temporary FP32 reconstruction/replay
does not survive a forward call. The native cache carries only an8-byte marker
per GDN layer. Prompt keys remain BF16 and state writes occur each256 prompt
tokens plus the prompt tail. Decode writes occur each8 or1 forwarded tokens.
Current output precedes boundary state rounding. The final sampled EOS/capped
token is not forwarded; total model calls remain `prompt_tokens+n-1`.

The first empty-cache token retains the unchanged native chunk readout. An
independent CPU diagnostic found BF16 rounding differences between that readout
and a sequential reduction, while their FP32 states were identical. The native
state is checked transiently and discarded; it never becomes a persistent
floating-point carrier. The original failed diagnostic is preserved and the
same exact-output threshold applies to the compatibility repair.

The verified primary source is [PACE v1](https://arxiv.org/html/2610.29545v1).
No verifiable official implementation was located. This is a method-consistent
reimplementation with explicitly declared conventions, **not official-code
byte-equivalence**. Rounding boundaries, FP64 encoder arithmetic using stored
FP16 scales, calibration aggregation, corpus selection and tail policy are
recorded in `method_spec.json` and the research audit.

The historical frozen generation protocol takes precedence over the request's
`deterministic=True` shorthand: its actual PyTorch deterministic-algorithms
flag is False. Original sampler, chat/thinking prompts, precision, seed1,
81920-token cap and FrozenV4 scorer are retained unchanged.

Before any GPU work, code, inputs, method and one-GPU permit are frozen.
The finite offline controller runs actualCUDA GatesA/B/C, one calibration,
freezes its mask, runs actual-mask GateC and full-model GateD, then admits the
fixed60 trajectories. Numerical thresholds are declared before the first GPU
gate and cannot be loosened after a failure. CPU mocks and local CPU tests
provide no GPU qualification or AIME credit.

The original offline parent runs one CPU finisher after actual controller and
worker exits. Complete60 results receive two fresh CPU FrozenV4 token
re-decodes, paired30 comparisons and physical buffer memory accounting.
Partial results retain true counts and failures without full-cohort accuracy.
All science, source, identities and costs are preserved on a failure. There is
no automatic GPU retry or redispatch of a started unit.
