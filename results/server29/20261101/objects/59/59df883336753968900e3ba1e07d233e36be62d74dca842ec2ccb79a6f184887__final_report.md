## Cache position / position ids / attention mask comparison
Root cause: manual decode relied on model-side inference from DynamicCache. In Ling's hybrid KDA cache, default get_seq_length does not provide the generation position; HF generate supplies cache_position explicitly.

## KDA recurrent-state handoff semantics
Prefill state is observable and matched. The failure was at cached decode input preparation, not prefill KDA state construction.

## Runtime hotspot
No severe per-token runtime pathology after isolating cached decode. The old long run was a wrong-trajectory problem.

## Minimal fix
Applied to manual decode loops: pass growing attention_mask and explicit cache_position on every cached decode call.

## Post-fix validation
POST_FIX_DECODE_PARITY=PASS. 4096-cap fixed manual problem 60 reached EOS at 3096 tokens in 243.94s.

## Remaining limitations
One-off 4096 manual run used a different seed policy than previous HF reference, so token-for-token free-generation identity was not expected there. Teacher-forced cached parity is the strict semantic validation.
