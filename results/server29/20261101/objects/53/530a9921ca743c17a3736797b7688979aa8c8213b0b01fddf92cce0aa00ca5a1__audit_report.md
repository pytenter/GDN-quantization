## Stage 1: Harness Generation
`HARNESS_GENERATION_TYPE = C. custom recurrent/KDA decode + manual token sampling`

The harness does not call `model.generate()`. It calls `model(**enc, use_cache=True)` for prefill and then repeatedly calls `model(input_ids=cur, past_key_values=past, use_cache=True)`.

`EOS_STOP_IMPLEMENTED = YES`: lines 654 and 675 check the sampled token against `stop_ids` and break. `EOS_MATCH = YES`: `stop_token_ids()` lines 393-401 includes `tokenizer.eos_token_id`, which local files define as 156895.

## Stage 2: Prompt / Chat Template
`CHAT_TEMPLATE_MATCH = PARTIAL`

The harness uses Ling's local chat template via `apply_chat_template`, not Qwen. Thinking mode is on by default because `enable_thinking` is not passed. The harness prompt is reconstructed in `prompt_audit.txt`; it begins with `<role>SYSTEM</role>detailed thinking on<|role_end|>` and ends with `<role>ASSISTANT</role>
<think>`.

Partial mismatch: the user message is not just the raw AIME problem; it is wrapped by `Solve the following math problem. Give the final answer in \boxed{} form... Solution:`.

## Final Classification
`ROOT_CAUSE_CLASSIFICATION = SAMPLING_CONFIG_MISMATCH_CONFIRMED`

No EOS stopping bug is confirmed. The harness has an EOS break and uses the correct EOS id. The confirmed problem is a legacy/manual generation protocol mismatch: no HF `generate()`, no top_k despite local config top_k=20, temperature differs from local config, and thinking-on prompt can encourage very long chains.

## Reporting Validity
`ARE_EXISTING_C128_20% RESULTS_VALID_FOR_FORMAL_REPORTING = ONLY_AS_LEGACY_PROTOCOL_DIAGNOSTIC`

`DO_FP_R128_C128_NEED_RERUN = PARTIAL`

Recommended canonical protocol: use Ling chat template with explicit `enable_thinking`, use HF `model.generate()` or an exact manual equivalent with explicit `eos_token_id=156895`, `pad_token_id=156892`, intended temperature/top_p/top_k, and save generated token ids plus finish reason.
