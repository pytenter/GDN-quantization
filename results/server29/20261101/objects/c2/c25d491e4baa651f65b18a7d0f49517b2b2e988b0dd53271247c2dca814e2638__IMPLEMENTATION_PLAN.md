# Implementation plan

This plan is prospective. None of its GPU stages were run in the design task.

## Stage 0 — freeze identities

1. Freeze hashes for V3 reducer, P1 accelerator, formal runner, formal
   quantizer, FP/Native/Hadamard/C5/C6 outputs, Frozen V4 labels, rotations,
   teacher token manifest, schemas, and layer list.
2. Freeze 60 sample IDs, seeds, 1,854,451 FP teacher tokens, static four-GPU
   allocation, and no-retry policy.
3. Refuse launch below 28 GiB free space.

## Stage 1 — offline sample metadata

Join frozen output manifests and Frozen V4 results. Compute generated length,
final token, and first divergence from FP without model execution. Hash inputs
and output. Verify the frozen accuracy totals exactly: FP 52, Native 18,
Hadamard 41, C5 33, C6 36.

## Stage 2 — implement read-only sidecars

1. Import the unchanged P1 reducer and formal model hooks.
2. Add a controlled-distortion observer that receives existing source/dequant
   tensors but cannot mutate them or reducer state.
3. Add a recurrent observer that calls only formal recovery helpers and saves
   drift scalars.
4. Add online function-space reduction; never save logits.
5. Implement fixed typed Parquet schemas, bounded queues, atomic write/hash/
   readback/done protocol, resume cursor, and fail-closed manifests.

## Stage 3 — CPU and synthetic tests

- formula/reference tests for L2, relative, max, MAE, drift increment, KL,
  margin, and delta NLL;
- exact row order and resume tests;
- NaN/inf preservation tests;
- Parquet schema/hash/readback tests;
- Top-32 equals deterministic Top-42 prefix test;
- no source-model mutation test.

## Stage 4 — GPU parity smoke

Run only two frozen samples and 64 total tokens:

- controlled sidecar versus unchanged V3/P1 state: byte-exact reducer parity;
- common-FP, formal rotation, formal quantizer, and token identity gates;
- both recurrent bundles, requiring exact repeated-FP state/logit hashes;
- online scalar metrics versus a small retained reference tensor calculation;
- artifact hash/readback and resume test;
- no memory creep.

Required pre-Full60 gates:

```text
CAPTURE_SIDECAR_REDUCER_PARITY = PASS
CAPTURE_SCALAR_REFERENCE_PARITY = PASS
RECURRENT_BUNDLE_FP_PARITY = PASS
CAPTURE_ARTIFACT_INTEGRITY = PASS
CAPTURE_SMOKE_2X64 = PASS
```

Any semantic/numerical/model failure stops the project; it is not retried.

## Stage 5 — resource smoke

Run the longest frozen prompt plus a bounded prefix using both recurrent
bundles. Require peak GPU memory below 23 GiB, host memory below the frozen
budget, bounded writer queues, no memory creep, and projected disk reserve at
least 15 GiB. This is still not Full60.

## Stage 6 — manual authorization boundary

Produce an implementation-readiness report. Stop. Full60 may start only after
all gates pass and the user separately authorizes it. A future authorized run
must never generate new answers or rescore; it uses frozen teacher tokens and
frozen endpoint labels only.

## Stage 7 — future Full60 execution order

1. Offline metadata freeze.
2. Controlled common-FP/P1 reducer capture, four static shards.
3. Recurrent bundle 1 (`FP+Native+Hadamard`), four static shards.
4. Recurrent bundle 2 (`FP+C5+C6`), four static shards.
5. Freeze and hash every shard before analysis.
6. Validate repeated FP equality and all 60×condition×token counts.
7. Produce layer ranking, tail comparison, drift/function trajectories,
   divergence-aligned stability, endpoint-group comparisons, and final report.

No downstream experiment is launched automatically.
