# GDN/KDA recurrent-state INT8 quantization handoff

## 1. Project goal

This project asks whether recurrent state in GDN/KDA language models can be stored through INT8 quantize/dequantize (QDQ) without losing long-horizon reasoning, and whether a learnable orthogonal basis can outperform a strong fixed Hadamard basis. Model weights are not quantized by this work.

## 2. Three-server map

| Handoff name | Hardware | Scientific role at snapshot |
|---|---|---|
| Qwen server | 4 x RTX 3090 | Qwen3.5-9B/GDN replay, metric audits, C5/C6 recurrent training, memory and topology closure |
| Ling server | 2 x RTX 4090 | Ling/KDA original Dense provenance and recurrent-training preparation |
| Third server | 8 x RTX 3090 | Ling deterministic V2, 256K offline analysis, L6/L7 recurrent training and current formal evaluation |

The historical `new4090` label refers to the third server but is a naming artifact; the audited hardware is 8 x RTX 3090. Network credentials are intentionally absent from Git. Exact non-secret roots and role provenance are in `SERVER_PROVENANCE.md`.

## 3. Model and quantization configuration

Qwen3.5-9B uses Gated DeltaNet recurrent state, INT8-C128 grouping, and a Key-side orthogonal rotation. Ling-3.0-tiny uses KDA recurrent state, INT8-R128 grouping, and a Value-side rotation. QDQ is applied to recurrent state that is written back into the next token step. For Ling, the corrected KDA kernel return is already expressed in the rotated Value basis; adding another prefill-endpoint rotation is invalid old semantics.

## 4. Canonical runtime

The frozen canonical task is AIME26 seed 1 with an 81,920-token cap and Strict V4 scoring. Canonical code, prompts, runtime provenance, and scoring rules are under `experiments/*/aime26/81920`, `results/aime26/81920`, `docs/PROTOCOL.md`, and `docs/SCORER_PROTOCOL.md`. Later 256K work is a separate sensitivity analysis.

## 5. Canonical AIME26 results

| Model | FP_STATE | Native INT8 | Fixed Hadamard | Fixed-Hadamard interpretation |
|---|---:|---:|---:|---|
| Qwen/GDN | 52/60 | 18/60 | 41/60 | 23 native losses rescued, 0 FP-correct cases lost |
| Ling/KDA | 44/60 | 23/60 | 28/60 | 7 native losses rescued, 2 native-correct cases lost |

Hadamard is therefore the current fixed baseline, not a placeholder.

## 6. GDN mechanism history

The selectively retained historical mechanism archive studies orientation, residual geometry, RMSNorm, out-projection, read/write observability, repeated accumulation, temporal survival, state-space pullback, functional risk, and structured rotation feasibility. These experiments are useful for mechanism hypotheses but do not supersede the frozen AIME result or the newer replay/provenance gates. `research-sync-2026-09-02` was imported only where the handoff tree lacked an equivalent canonical copy.

## 7. KDA mechanism history

The Ling archive includes architecture/state-semantics auditing, commutator, decay-scalarization, persistent-error decomposition, prefill localization, kernel equivariance, and final-writeback localization. Its most important implementation resolution is the corrected Value-basis lifecycle: kernel-returned recurrent state must not receive a redundant endpoint rotation.

## 8. Fixed Hadamard baseline

Hadamard is cheap, deterministic, orthogonal, and already produces material E2E recovery. Qwen uses Key-Hadamard because C128 Key-oriented state geometry is the tested canonical interface. Ling uses Value-Hadamard because R128 aligns with the KDA Value dimension and corrected kernel semantics. Arbitrary-orthogonal and numerical-closure branches establish the implementation interface; they do not establish that every orthogonal basis preserves reasoning equally well.

## 9. Learnable Dense rotation history

The earlier Hadamard-initialized Dense-State and Dense-Functional rotations explored learnable orthogonal bases through Cayley-style parameterization. They provided valuable implementation, provenance, and headroom evidence, but their training state was reset from the FP teacher at each token. Last-20 Qwen E2E results (17 FP, 4 Native, 13 Hadamard, 12 Dense-State, 8 Dense-Functional) are archived as real negative evidence for those checkpoints, not as a rejection of recurrent-aware learning.

## 10. Metric and replay findings

Qwen teacher-forced replay contains 60 paired trajectories, 24 layers, and 3,708,902 token-conditions. M5 p95 has within-rotation failure AUROC 0.851 with CI [0.7315, 0.9462]. Across rotations, however, raw M5 has a scale mismatch: Hadamard can score worse locally yet reason much better. FP normalization, ratios, deltas, logarithms, quantile normalization, rescue pairing, and coordinate checks did not produce a validated cross-rotation target. `ROTATION_AWARE_M5_GATE = FAIL`; persistent future-KL replay was not completed. Use M5 for diagnosis, not basis selection.

## 11. Why old Dense is not recurrent-aware

Old training was `FP teacher state -> one-step QDQ perturbation -> loss -> reset`. Formal generation is `INT8 student state -> QDQ -> writeback -> next token -> accumulated error`. Provenance audits find exact/numerically equivalent QDQ but failing recurrent-training and writeback gates. C5/C6 and L6/L7 were created specifically to put the learned rotation inside real recurrent history with explicit detach and BPTT boundaries.

## 12. Qwen C5/C6 current state

C5/C6 passes AIME-overlap, step-0 parity, exact-QDQ, recurrent writeback, provenance, gradient, and BPTT-boundary gates. Single-GPU H32 is too large for sustained training although the memory audit finds no leak. Dual-GPU forward topology passes 240 state/QDQ checkpoints plus loss, writeback, and BPTT checks. Bitwise gradient/update comparison fails, but single-GPU repeats are also non-bitwise and strict deterministic mode cannot cover the cumsum implementation. Under the preregistered frozen envelope, the current topology gate is still FAIL, so no formal C5/C6 AIME run has started.

The follow-on trajectory-equivalence experiment was **RUNNING** at the audit snapshot. Eight immutable single-GPU analyses are archived; the growing ninth run was deliberately not copied.

## 13. Ling recurrent training current state

L4/L5 remain old single-step checkpoints. L6/L7 implement recurrent-aware writeback, passed training/final-R/orthogonality/sanity gates, and have metadata but no binaries in Git. L6 formal evaluation was **RUNNING/PARTIAL** on the third server: seven sample outputs existed, with no final report or completion marker. L7 formal evaluation is pending. These statuses must not be upgraded without natural completion plus frozen scoring evidence.

## 14. Ling determinism closure

The original runtime passed within a process but failed across fresh processes. First-divergence work localized the variance to process-local Triton autotuning/numerical configuration. The deterministic 16-document V2 replication, executed on the third 8x3090 server, passes fresh-process reproducibility with zero observed noise. Its Future-KL AUC means/medians are Native 0.031744/0.016550, Hadamard 0.018873/0.009969, Dense-State 0.028116/0.009978, and Dense-Functional 0.016269/0.009924. No credible persistent Dense headroom is established.

## 15. Ling 256K long-horizon findings

The final offline analysis scores FP 21/30, Native INT8_R128 9/30, and Value-Hadamard 17/30. The branch contains compact per-sample trajectory metadata, post-divergence stability, failure taxonomy, rescue/termination/oscillation summaries, scoring, provenance, and reports. Full responses are server-resident only. The result supports Hadamard recovery at longer caps but is not interchangeable with the canonical 60-sample, 81,920-token comparison.

## 16. Negative and superseded results

- `QWEN_ROTATION_SURROGATE_VALIDATION_V1` and `QWEN_ROTATION_AWARE_M5_VALIDATION_V1`: current negative metric evidence.
- Old Dense C3/C4 and L4/L5: valid measured checkpoints with superseded single-step training semantics.
- Redundant Ling prefill-endpoint rotation: invalid old KDA semantics.
- Qwen `gdn_rotation_headroom_v1` and `gdn_postconv_structured_rotation_v1`: historical failed/closed prototypes.
- Strict scorer V1/V2/V3 and 65,536-token runtime smoke: legacy/superseded by the frozen protocol.
- Ling nondeterministic V1: historical diagnostic resolved by first-divergence closure and deterministic V2.

## 17. Current blockers

- Qwen needs a sustainable recurrent horizon and an accepted functional/numerical topology criterion before formal training/evaluation.
- Ling needs natural completion and scoring of L6, later L7 evaluation, and closure of the PARTIAL recurrent-memory audit.
- Cross-rotation surrogate validity remains open; raw M5 cannot currently drive optimization.
- Running artifacts cannot be treated as immutable evidence until completion markers and hashes exist.

## 18. Exact next steps

1. Wait for Qwen trajectory run and Ling L6 evaluation to finish without intervention; then archive only finalized compact outputs.
2. Evaluate Qwen dual/single trajectories against the preregistered intrinsic-variability envelope and freeze the topology decision.
3. Establish a resource-feasible multi-step Qwen horizon; train C5/C6 only after the gate passes.
4. Close Ling cache/QDQ/validation/sustained-memory probes after formal generation no longer occupies the runtime.
5. Complete Frozen V4 scoring for L6, then run L7 evaluation under the same deterministic runtime.
6. Compare learned recurrent-aware rotations against Hadamard on the frozen reasoning protocol; treat replay metrics as diagnostics unless separately validated across rotations.
